# 10 · 模块 G：工程交付与第三方协同（D10 + D11）

> 解决断点⑤发货→安装、⑥安装→验收回款。这是公司最大成本开支项（工程技术部 23 人 + 7 个区域组），也是本项目差异化能力最集中的地方。
> 本模块的四条硬约束：**派工必须有风场（BR-04）**、**第三方只能用小程序（BR-08）**、**下载只能拿水印件（BR-07）**、**照片水印后不留原图**。
> 规则编号 `FR-ENG-nn` / `FR-THD-nn`。

---

## 1. 模块目标

| 目标 | 定义 | 反面（现状） |
|---|---|---|
| 派工有依据 | 派工单的物料依据来自发货明细 + 工程 BOM | 到了现场才知道缺什么 |
| 销项可核对 | 按点位清单装一个勾一个，耗用差异可解释 | 靠人脑记装了哪些 |
| 质量有证据 | 每台机组有安装/调试记录 + 水印照片 + AI 初审 | 照片在个人手机里 |
| 整改有闭环 | 问题→通知→整改→复核→关闭，超时升级 | 问题口头说，没人跟 |
| 费用可归集 | 现场费用直接进项目成本，日可见 | 月底报销才知道花了多少 |
| 档案可查 | 一机一档，扫码即知这台装了什么 | 要问老员工 |

## 2. 施工班组与人员（准入与账号生命周期）

### 2.1 账号生命周期（BR-08 的落地）

```
班组准入：注册 → 资质审核 → 现场考察 → 培训考核 → 合格名录
人员入场：身份证 + 资质证书 + 保险 + 安全培训记录 在线提交
          → 工程部审核 → 行政开通账号（PENDING）
项目授权：工程部加入项目成员 + 分配可见文件范围 → 账号 ACTIVE
现场作业：仅小程序可登录（PC 返回 403）
离场冻结：工程部移出项目 → FROZEN（数据保留）
重新入场：校验资质/保险有效期 → 解冻
```

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-ENG-01 | 班组档案 | 所属公司（关联供应商）、班组长、成员、资质等级、历史项目表现、评分 |
| FR-ENG-02 | 人员档案 | 姓名、身份证（**加密存储**）、电话、资质证书（类型/编号/有效期）、保险有效期、培训记录 |
| FR-ENG-03 | 入场资料 | 在线提交四类材料；缺项不可提交；材料有效期校验（保险/培训过期直接拒绝） |

| FR-ENG-05 | 项目授权 | 加入 `thd_worker_project`（授权起止日）；授权后可见该项目已发布文档 |

## 10. 异常处理

| 场景 | 行为 |
|---|---|
| 派工单未选风场 | 阻断（BR-04），弹窗二选一：补选/申请新建 |
| 发货了但工程部不知道 | 出库后 24h 内自动生成派工单并推送；未生成则提醒 |
| 现场断网 | 离线队列；联网同步；冲突转草稿 |
| 照片上传失败 | 本地保留 + 重试；连续 3 次失败提示检查网络 |
| AI 检测误判（监理认为合格） | 监理可"否决 AI 结果"并填理由；记录到 ai_feedback |
| 施工人员离职/换人 | 冻结账号；未完成任务转派；整改中任务重新指派 |
| 业主拒收 | 验收结果填"不通过"+ 原因；生成整改单；不计入"验收一次通过率"的分子 |
| 一机装了 3 个产品 | 机组档案挂 3 个 SBOM 子项；不新建 3 个机组 |
| 现场缺件要补货 | 走 INV 补货（BR-05 安全件可先发后签）；补货单自动带项目与派工单 |
| 小程序包超限 | 分包加载；文档预览走 CDN + 按需 |

## 11. 验收要点

1. 发货出库 → 自动生成派工单，物料明细 = 发货明细。
2. 派工单未选风场 → 拒绝（BR-04）。
3. 现场拍照上传 → 服务端合成水印，原图不存在。
4. 断网填 10 条日志 + 5 张照片 → 联网同步成功，无重复，冲突项转草稿。
5. 销项 96% → "提交完工"置灰并显示剩余行数。
6. 销项耗用超计划 5 件 → 必须选原因。
7. AI 检测不合格 → 自动生成整改单草稿；监理确认后正式下发。
8. 整改超期 → 升级工程经理 + 红灯卡。
9. 扫机组二维码 → 展示该机组 3 个产品、安装日期、最近 3 次工单。
10. R17 用 PC 登录 → 403；用小程序可看图纸但下载按钮不存在。
11. 供应商门户查看订单 → 无单价与金额字段（接口返回里就没有）。
12. 保险过期人员被授权 → 拒绝并提示具体过期项。
