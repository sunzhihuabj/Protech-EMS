# 05 · 模块 B：项目与工程变更（D02）

> 解决断点②合同→生产。项目是"一个项目号走到底"的执行载体：合同归档即立项，任务分解驱动各部门，ECO 管住变更。
> 规则编号 `FR-PRJ-nn`。

---

## 1. 模块目标

| 目标 | 定义 | 反面 |
|---|---|---|
| 立项自动 | 合同归档即生成项目，带客户/合同/交期 | 靠人手工建项目 |
| 任务可追 | 每个任务的承担部门、责任人、产出物、审批明确 | 任务只在会议纪要里 |
| 依赖可算 | 前置未完成则后续不能开工；关键路径可视 | 谁先谁后靠喊 |
| 变更受控 | ECO 走审批，影响采购/生产/进度可评估 | 图纸改了工艺不知道 |
| 进度可见 | 甘特 + 里程碑 + 资源负载一屏 | 靠问项目经理 |

### 2.2 模板可配置

管理员可创建多个模板（如"标准系统集成""纯设备供货""技改加装""内部研发"），每个任务可设：
名称、WBS 层级、承担部门、默认角色、工期（天）、是否可选（项目经理可决定启用）、输入文件要求、输出文件要求、是否需要审批。

## 4. 功能需求

### 4.1 立项

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-PRJ-01 | 自动立项 | 合同状态→PERFORMING 时自动创建项目：名称=合同项目名、客户、关联合同、计划起止（按交货期倒推，默认工期 120 天可配） |
| FR-PRJ-02 | 手动立项 | 支持内部研发/无合同项目手工创建（需选"项目类型"） |
| FR-PRJ-03 | 双号关联 | `prj_project.project_no`（执行号 `PRJ-YYYY-NNNN`）与 `md_project.project_code`（档案号 `PJYYYY-NNNN`）建立 1:1 或 1:N 关联 |
| FR-PRJ-04 | 项目经理指派 | 立项时必填项目经理；未指派时项目状态为"未启动"，出现在 PMO 待办 |
| FR-PRJ-05 | 模板选择 | 立项时选模板（默认按项目类型匹配）；生成任务树 |
| FR-PRJ-06 | 预算初始化 | 可从报价成本或合同额 × 历史毛利率带出初始预算（可改） |

### 4.2 任务与 WBS

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-PRJ-07 | 任务生成 | 按模板生成任务树，`wbs_code` 形如 `1`、`1.2`、`1.2.3`；初始状态"未开始" |
| FR-PRJ-08 | 日期推算 | 按模板工期 + 依赖关系自动推算计划起止；项目起止为总约束 |
| FR-PRJ-09 | 指派责任人 | 项目经理从拥有对应角色的人员中选择（下拉带角色过滤） |
| FR-PRJ-10 | 调整日期 | 拖甘特或表单改；改了自动重算后续依赖任务的日期；冲突提示 |
| FR-PRJ-11 | 拆分任务 | 一个任务可拆为多个子任务并行；拆分后父任务变为汇总节点（进度取子任务加权） |
| FR-PRJ-12 | 临时任务 | 支持新增计划外任务（不挂在模板上，标 `is_temp=1`） |
| FR-PRJ-13 | 可选任务 | 模板中 `is_optional=1` 的任务，立项时项目经理可勾选是否启用 |
| FR-PRJ-14 | 开工 | 责任人点"开始任务"→ 进行中 + 记实际开始时间；前置未完成则按钮灰显并提示卡在哪个任务 |
| FR-PRJ-15 | 过程文件 | 可随时上传草稿（归档到项目对应阶段文件夹），不影响任务状态 |
| FR-PRJ-16 | 完成任务 | 必须上传产出物（若模板要求）+ 填完成说明；配置了审批则进审批流 |
| FR-PRJ-17 | 审批 | 审批人通过→已完成+记实际完成；驳回→退回进行中并填理由 |
| FR-PRJ-18 | 逾期自动标记 | 每日定时：`now > plan_end` 且未完成 → 状态 DELAYED，个人工作台高亮，进红灯候选 |
| FR-PRJ-19 | 暂停 | 项目经理或责任人可暂停（填原因）；暂停期间不计入工期（计划日期顺延） |
| FR-PRJ-20 | 取消 | 范围变化时取消（不删除）；关联文件保留；取消需项目经理确认 |
| FR-PRJ-21 | 任务依赖 | 支持 FS/SS/FF/SF 四种 + 滞后天数；前置未完成则后续不可开工 |
| FR-PRJ-22 | 关键路径 | 甘特图自动计算关键路径并以红色显示；关键路径任务延期 → 项目预警 |

### 4.3 甘特与资源

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-PRJ-23 | 项目甘特 | 展示任务时间条、依赖连线、里程碑、今日线；支持拖拽调整（需 `project:task:adjust_date`） |
| FR-PRJ-24 | 我的任务甘特 | 跨项目叠加，不同项目不同颜色；可看出时间冲突 |
| FR-PRJ-25 | 部门负载 | 部门经理看本部门每人任务甘特；冲突（同一人同期 >100%）高亮 |
| FR-PRJ-26 | 拖拽校验 | 拖拽后校验依赖（前置是否满足）与资源冲突；冲突给提示但不强制阻断（允许"带冲突保存"并记录） |
| FR-PRJ-27 | 里程碑 | 项目可设里程碑（无工期，只标记关键节点）；里程碑偏差 >7 天 → 预警 |

### 4.4 项目成员与权限

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-PRJ-28 | 成员维护 | 项目经理可增删成员，指定项目内角色（技术/采购/生产/工程/财务接口人） |
| FR-PRJ-29 | 权限联动 | 加入成员后自动获得该项目的 `PROJECT` 数据范围（可看项目文件与任务） |
| FR-PRJ-30 | 移交 | 项目经理变更需 R02 审批；原经理转只读 |

### 4.5 工程变更 ECO

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-PRJ-31 | 发起 ECO | 技术经理在项目详情发起；必填变更原因、变更内容、影响分析（采购/生产/进度）、**旧料处置方案（BR-09）**、新版本文件 |
| FR-PRJ-32 | 影响部门自动判断 | 按变更内容判断受影响部门（涉 BOM→采购/工艺/生产；涉图纸→工艺/生产；涉交期→商务/工程） |
| FR-PRJ-33 | 会签 | 受影响部门负责人会签 → 批准/驳回 |
| FR-PRJ-34 | 变更中标记 | 审批过程中原文件仍可用但标"变更中"（黄标提示下游） |
| FR-PRJ-35 | 生效 | 批准后：新文件替换旧文件并升版（版本号+1）；通知所有受影响任务责任人；旧版本归档留存 |
| FR-PRJ-36 | 联动 BOM | 若 ECO 涉及 BOM，自动创建 `bom_change` 记录并与 ECO 关联（两个编号统一为 ECN） |
| FR-PRJ-37 | 变更看板 | 列表展示 ECO 数量、平均闭环天数、超期未闭环 |

### 4.6 项目阶段门控

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-PRJ-38 | 门控点 | 六阶段各设一个 Gate：阶段内任务全部完成 + 关键产出物齐备 → 可提交评审 |
| FR-PRJ-39 | 评审 | Gate 评审需 R02 或指定评审人通过；未通过不得进入下一阶段 |
| FR-PRJ-40 | 例外 | 紧急情况可"带条件通过"（记录条件与期限），到期未闭环自动提醒 |

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| BR-PRJ-01 | 任务不可物理删除，只能取消 |
| BR-PRJ-02 | 前置任务未完成时，后续任务"开工"按钮不可用（不是"提示后允许"） |
| BR-PRJ-03 | 已通过审批的任务产出物不可替换，只能新建版本（走 ECO） |
| BR-PRJ-04 | 项目关闭需满足：无未完成任务、无未验收机组、回款率 100% 或已标坏账、质保金已释放 |
| BR-PRJ-05 | 关键路径任务延期 >3 天自动生成红灯卡 |
| BR-PRJ-06 | ECO 未附旧料处置方案禁止提交（BR-09） |
| BR-PRJ-07 | 同一项目同一时间只能有一个"进行中"的 ECO 关联同一份 BOM（防并发改） |

## 6. 异常处理

| 场景 | 行为 |
|---|---|
| 模板任务数与项目实际不符 | 允许增删任务；增删记入项目变更日志 |
| 依赖成环 | 保存时检测，提示"存在循环依赖：A→B→C→A"并拒绝 |
| 拖拽导致前置晚于后置 | 提示冲突，可选择"自动顺延后续"或"取消" |
| 责任人离职 | 任务自动转给其部门负责人，推送通知；转交留痕 |
| 任务无产出物但要完成 | 拒绝（若模板要求）；确需例外由项目经理填理由并记录 |
| ECO 生效后下游未同步 | 系统发"待同步"提醒，并在下游文件上标"上游已变更" |
| 项目已关闭但要重启 | 不允许改状态，新建项目并关联原项目 |

---

## 7. 验收要点

1. 合同归档 → 自动创建项目，任务树 6 阶段 20+ 任务，日期按工期推算。
2. 前置任务未完成 → 后续"开工"灰显，提示卡在哪个任务。
3. 拖拽关键路径任务 +5 天 → 后续依赖任务自动顺延，项目结束日同步推后。
4. 一人同期被排 130% 负载 → 部门负载视图高亮。
5. 发起 ECO 不填旧料处置 → 拒绝（BR-09）；填后影响部门自动勾选采购/工艺/生产。
6. ECO 批准 → 文件升版 V1→V2，旧版留存，下游收到通知。
7. Gate 评审未通过 → 下一阶段任务仍可看但不可开工。

**声明：本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。**
