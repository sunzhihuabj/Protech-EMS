# 20 · 待确认清单与勘误表

> 本册是规格包的**唯一待确认事实源**。00 册 §四第 7 条与 16 册 §一均要求"遇到待确认项按默认假设执行"——所指清单即本册。
> 使用方式：执行 Agent 遇歧义 → 查本册 → 有 Q/AMB 编号则按"建议默认值"执行并记 `docs/ASSUMPTIONS.md`；无编号则新建并回报。
> 版本 V1.0｜编制 2026-10-29｜配套：18（风险评估）、19（需求深化）

---

## 一、使用说明

### 1.1 三类条目的区别

| 类型 | 含义 | 处理方式 |
|---|---|---|
| **Q-xx 待确认** | 信息缺失，需人决策 | 按"建议默认值"先做，决策后可能返工；标注返工影响面 |
| **AMB-xx 歧义** | 表述存在多种理解，规格未收敛 | 按"建议解释"执行；若理解错，影响面通常小于 Q |
| **E-xx 勘误** | 规格内部自相矛盾或数字错误 | 直接按"应为"执行，不需决策（除标注需评审者） |

### 1.2 关闭规则

| 状态 | 含义 | 谁可置为已关闭 |
|---|---|---|
| 待决策 | 未有人表态 | — |
| 已定（决策） | 决策人签字/邮件确认 | 该条"决策人" |
| 已定（默认） | 超过截止日未决策，按默认值执行 | 产品负责人 |
| 已作废 | 因范围变更不再需要 | 产品负责人 |

**铁律**：任何 Q 超过截止日 5 个工作日未决策，自动转为"已定（默认）"，并记入月报"决策积压"。不允许因等待决策而停工（16 册 §一）。

### 1.3 优先级定义

| 级别 | 含义 | 时限 |
|---|---|---|
| **P0** | 影响数据模型或范围，不定则无法开工 | 3 个工作日内 |
| **P1** | 影响某一域的实现方式，可在该域开工前定 | 该域切片开始前 |
| **P2** | 影响体验或运营，可上线后调整 | 上线前 |

## 七、关闭流程与模板

### 7.1 流程

```
提出（任何人） → 登记本册（编号/影响/选项/建议默认值） → 指派决策人 → 截止日
   → 决策（签字/邮件） → 更新"状态" → 若改变默认值 → 评估返工面 → 记 CHANGELOG
   → 同步受影响册（02 模型/04—12 规则/16 切片/17 用例）
```

### 7.2 决策记录模板

```markdown
### Q-xx 决策记录

- 决策人：            - 决策日期：
- 结论：□ 采纳建议默认值  □ 采纳其他选项（写明）  □ 延后（写明新截止日）
- 理由：
- 返工影响：□ 无  □ 改表结构（表名/字段）  □ 改规则（BR/FR）  □ 改范围（域/卡点）
- 需同步的册：02 / 03 / 04—12 / 16 / 17 / 18 / 19
- 同步完成：□ 是（日期）  □ 否（原因）
```

## 八、给执行 Agent 的三条硬规则

1. **先查本册再动手**：遇到"这个字段是必填吗""这个状态能不能跳""这个阈值是多少"之类的问题，先查 Q/AMB；查到就按默认值做，并在 `docs/ASSUMPTIONS.md` 记一行（编号 + 采用值 + 日期）。
2. **查不到就新建并回报**：格式 `Q-NEW-{日期}-{序号}`，写清"问题/我的处理/影响面"，不要沉默，也不要自行扩大解释。
3. **不得修改本册的结论**：本册只能由产品负责人更新；Agent 只能在 `ASSUMPTIONS.md` 里记录"我采用了什么"。

**声明：本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。**
