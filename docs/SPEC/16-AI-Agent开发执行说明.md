# 16 · AI Agent 开发执行说明（开发契约）

> **本册是给你（AI 编程 Agent）的执行手册。** 前十五册回答"做什么"，本册回答"怎么干、按什么顺序、什么算干完、什么不许干"。
> 本册优先级高于你的默认习惯：当你的经验与本册冲突时，**以本册为准**；本册未规定的，按 Spring Boot / Vue 最佳实践，并记入 `docs/ASSUMPTIONS.md`。

**模块间调用规则（可拆分的前提）**：
- `module-x` 只能通过自己的 `api` 包（`XxxApi` 接口 + DTO）对外暴露能力；
- **禁止**跨模块直接注入对方的 Mapper 或访问对方的表；
- 跨模块需要数据时，通过 `XxxApi` 或事件（`ApplicationEventPublisher`）；
- 每个 module 内部三层：`controller` → `service` → `mapper`。

## 四、工程规范

### 4.1 分层与命名

| 层 | 命名 | 职责 |
|---|---|---|
| Controller | `XxxController` | 参数校验、权限注解、调用 Service、返回统一包；**不写业务逻辑** |
| Service | `XxxService` / `XxxServiceImpl` | 业务规则、事务边界；顶部注释标 FR 编号 |
| Mapper | `XxxMapper` | SQL；复杂查询写在 XML |
| DTO | `XxxReq` / `XxxResp` | 出入参；用 `@Valid` 校验 |
| Entity | `Xxx` | 与表一一对应；继承 `BaseEntity`（含审计字段） |

### 4.2 统一响应包

```java
public class ApiResponse<T> {
    private int code;        // 0=成功
    private String message;
    private T data;
    private String traceId;
}
```

### 4.3 错误码表

| HTTP | code | 含义 | 说明 |
|---|---|---|---|
| 200 | 0 | 成功 | — |
| 400 | 1001 | 参数校验失败 | `data.errors` 字段级错误 |
| 401 | 2001 | 未登录/会话过期 | 前端跳登录 |
| 403 | 2002 | 无权限 | `data.missingPerm` |
| 403 | 2003 | 数据范围外 | — |
| 404 | 3001 | 资源不存在 | — |
| 409 | 4001 | 并发冲突 | `data.currentVersion` |
| 422 | 5001 | 业务规则阻断 | **硬卡点统一 422**，`data.blockCode=BR-0x` |
| 429 | 6001 | 频率限制 | — |
| 500 | 9001 | 系统错误 | 只返回 traceId，不暴露堆栈 |

**硬卡点必须返回**：
```json
{"code":5001,"message":"合同评审必须关联项目编码","data":{
  "blockCode":"BR-01","suggestion":"请先建档取码","link":"/mdm/project/new"},"traceId":"..."}
```

### 4.4 必做的技术细节

| 项 | 要求 |
|---|---|
| 金额 | `BigDecimal`；DB `DECIMAL(18,2)`；禁止 `double/float`；前端传字符串防精度丢失 |
| 日期 | `LocalDate`/`LocalDateTime`；时区 `Asia/Shanghai`；`DATETIME` 存储 |
| 编码 | 只用 `CodeSequenceService`；禁止拼字符串 |
| 权限 | Service 写操作第一行 `@RequirePermission`；查询必须经 `DataScopeInterceptor` |
| 审计 | AOP 切面统一拦截写操作，自动写 `sys_operation_log`（含 before/after） |
| 事务 | 多表写必须 `@Transactional`；编码取号与业务写入同事务 |
| 幂等 | 库存事务/导入/推送必须带幂等键，重复请求返回首次结果 |
| 乐观锁 | 单据更新带 `version`，影响行数 0 → 抛 409 |
| 脱敏 | `@Sensitive(perm="...")` 注解 + Jackson Serializer，服务端完成 |
| 日志 | `log.info("...{}", arg)`；禁止字符串拼接；敏感字段脱敏 |
| 异常 | 业务异常 `BizException(code, msg)`；全局 `@RestControllerAdvice` 兜底 |
| 空值 | 返回集合不返回 null；单对象用 `Optional` |
| 分页 | 统一 `PageReq{pageNum,pageSize}`，默认 1/20，最大 200 |
| 前端权限 | `v-permission` 只控显隐，**不得作为唯一防线** |
| 前端金额 | 显示统一格式化（千分位 + 2 位）；编辑用输入框限制 |
| 移动端 | 扫码/销项/日志页按 375px 设计，按钮 ≥44px |

### 4.5 数据库规范

- 表名 `蛇形`，字段 `蛇形`；主键 `id BIGINT UNSIGNED AUTO_INCREMENT`。
- 所有业务表含 `deleted TINYINT DEFAULT 0`、`created_by/created_at/updated_by/updated_at`。
- 索引命名 `idx_{表}_{字段}`、`uniq_{表}_{字段}`。
- 枚举字段 `VARCHAR(24)` 存英文 code。
- JSON 字段只用 `JSON` 类型，不建索引。
- **禁止外键约束**（用应用层保证；便于分库与数据迁移）。
- Flyway 管理 DDL；**脚本只增不改**。

## 九、需求变更控制

收到"顺便加个功能"时：

1. **判定范围**：是否在 01 册 4.1 内？
   - 不在 → 记入 `docs/BACKLOG.md`「后续版本池」，回复"已记录，本期不做"，**不实现**。
   - 在范围但影响数据模型 → 必须先回报"需改 02 册第 X 表 Y 字段，影响 A/B/C 三处"，等确认。
   - 在范围且不影响模型 → 实现，并新增 FR 编号。
2. **评估五要素**：影响范围、工期变化、成本变化、风险变化、干系人一致性 → 写 `DECISIONS.md`。
3. **留痕**：`docs/CHANGELOG.md` 记录（日期、内容、FR 编号、影响）。
