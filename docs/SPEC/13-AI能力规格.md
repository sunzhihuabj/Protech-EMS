# 13 · AI 能力规格（D14）

> 本册把 A 的"AI 双模型"落成可开发、可验收、可运营的规格。
> 三条底线：**内网私有化（禁公网）**、**AI 不自动判定（必须人工复核）**、**模型不可用不阻塞业务**。
> 规则编号 `FR-AI-nn`；接口编号 `AI-001`—`AI-104`。

---

## 1. 架构：为什么必须有 AI 网关

```
业务模块（合同/质检/工程/物料…）
        │  只依赖 AiGatewayService 接口
        ▼
  ┌─────────────────────────────────┐
  │  projlife-ai-gateway（独立进程） │
  │  · 路由（data / image）          │
  │  · 健康检查 + 熔断              │
  │  · 超时控制（30s / 20s）         │
  │  · 重试（1 次）                  │
  │  · 降级（返回 DEGRADED）         │
  │  · 调用日志（脱敏）              │
  │  · mock 开关                     │
  └─────────────────────────────────┘
        │  内网 HTTP（不经过公网）
        ▼
  模型服务器 A（数据推理）  模型服务器 B（图像识别）
```

**四条硬约束**：

| 编号 | 约束 | 实现 | 验证 |
|---|---|---|---|
| BR-AI-01 | 业务代码不得直连模型 | 只允许注入 `AiGatewayService`；代码评审 + 静态扫描 | 构建期扫描 `http` + 模型域名 |
| BR-AI-02 | 不得调用公网 AI | 禁用关键字扫描：`openai`/`dashscope`/`qianfan`/`hunyuan`/`ernie`/`azure.*openai` | CI 阶段失败即阻断 |
| BR-AI-03 | AI 不自动判定 | `qms_inspection.result`、`ct_contract` 的正式字段只能人写 | 代码层：AI 结果只写入 `*_ai_json` 字段 |
| BR-AI-04 | 模型不可用不阻塞 | 超时/失败 → DEGRADED → 业务走人工模式 | 关掉模型跑全流程 |

## 3. 输出契约与质量要求

### 3.1 通用响应包

```json
{
  "code": 0,
  "aiCode": "AI-001",
  "modelVersion": "contract-risk-v1.2",
  "promptVersion": "p3",
  "isMock": false,
  "confidence": 0.86,
  "data": { },
  "warnings": ["质保金条款识别置信度较低"],
  "traceId": "01J..."
}
```

**必带字段**：`aiCode`、`modelVersion`、`promptVersion`、`confidence`、`isMock`、`traceId`。
**为什么**：没有版本号就无法复现"为什么当时这么判"；没有 confidence 就无法做低置信降级。

### 3.2 置信度分级与处置

| 置信度 | 展示 | 处置 |
|---|---|---|
| ≥0.85 | 正常显示 | 可一键采纳 |
| 0.60—0.85 | 黄色标记"建议复核" | 可采纳但提示 |
| <0.60 | 灰色显示"仅供参考，建议人工录入" | **不提供"采纳"按钮**，避免误导 |
| 服务降级 | 显示"AI 暂不可用，请人工填写" | 表单可正常录入，不阻塞 |

### 3.3 六维质量维度（验收用）

| 维度 | 定义 | 检验方法 |
|---|---|---|
| 事实正确 | 提取/判断与文件事实一致 | 人工标注 50 份样本，比对 |
| 信息完整 | 该有的字段不漏 | 字段漏检率 |
| 格式合规 | 返回符合 JSON Schema | Schema 校验 100% |
| 表达合适 | 建议可执行、无空话 | 人工评分（1—5，≥3.5 合格） |
| 来源可靠 | 结论能指向原文位置 | 抽样 30 条核对 bbox/页码 |
| 支持下一步 | 结果可直接用于业务动作 | 采纳率 |

### 3.4 量化验收阈值（S9 切片验收）

| 指标 | 阈值 | 说明 |
|---|---|---|
| 合同信息提取字段准确率 | ≥85%（关键 6 字段 ≥95%） | 关键：金额/对方/签订日/质保/付款条件/项目名 |
| 合同风险识别召回率 | ≥70% | 人工标注的高/中风险中，AI 命中的比例 |
| 风险误报率 | ≤30% | 避免"什么都报"导致没人看 |
| 来料外观检测准确率 | ≥80% | 与人工判定一致率 |
| 施工照片问题检出率 | ≥75% | 人工标注的问题中 AI 检出的比例 |
| 物料模糊匹配 Top5 命中率 | ≥90% | 目标物料在前 5 条 |
| 低置信降级触发率 | 记录即可 | 不是越低越好，是"该降就降" |
| 平均响应时间 | 数据 ≤8s，图像 ≤6s（P95） | 不含排队 |
| 采纳率 | 合同提取 ≥70% | 采纳率过低说明质量差 |

## 4. 降级链（每层都要能跑）

```
① 模型健康检查失败 → 立即返回 DEGRADED（不重试，避免拖死业务）
② 请求超时（30s/20s）→ 中断 → 重试 1 次 → 仍失败 → DEGRADED
③ 返回格式非法（JSON 解析失败/Schema 不符）→ 视为失败 → DEGRADED
④ 置信度 <0.60 → 返回结果但标 low_confidence，前端不给"采纳"
⑤ mock 模式开启 → 返回预置样例，标 isMock=true
```

**业务侧的降级要求**（每个调用点都必须实现）：

| 调用点 | 降级后 |
|---|---|
| 合同风险分析 | 显示"AI 不可用"，合同仍可正常评审归档 |
| 合同信息提取 | 表单可手工录入，归档不受影响 |
| 施工照片检测 | 转"人工复核"队列，监理逐张看 |
| 物料模糊匹配 | 转普通搜索（按名称/编码） |
| 安全库存建议 | 用手工设定的上下限 |
| 8D 根因建议 | 不显示，人工填 D4 |
| 验收报告生成 | 用模板填空 |

## 5. 人工复核闭环（模型迭代的数据来源）

### 5.1 三道留痕

| 数据 | 表 | 用途 |
|---|---|---|
| AI 原始输出 | `ai_call_log.response_json` | 复盘"当时 AI 说了什么" |
| 人工修改 | `ai_feedback`（ai_value / human_value / is_correct） | 训练与评测样本 |
| 最终采用值 | 业务表正式字段 | 真实标签 |

### 5.2 功能需求

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-AI-01 | 统一网关 | 业务只调 `AiGatewayService`；4 个方法：`analyzeContractRisk` / `extractContractInfo` / `detectImage` / `matchMaterial`（按需扩展） |
| FR-AI-02 | 路由 | 按 `aiCode` 前缀路由：AI-0xx → 数据模型；AI-1xx → 图像模型 |
| FR-AI-03 | 健康检查 | 每 60s 探活；连续 3 次失败 → 熔断 5 分钟 |
| FR-AI-04 | 超时与重试 | 数据 30s、图像 20s；超时中断；失败重试 1 次（仅对 5xx/超时，不对 4xx 重试） |
| FR-AI-05 | 降级 | 返回 `DEGRADED` + 提示语；不抛异常给业务 |
| FR-AI-06 | mock 模式 | 配置开关；14 个接口各有预置样例；mock 时 `isMock=1` |
| FR-AI-07 | 调用日志 | 记 ai_code/biz_type/biz_id/请求（脱敏）/响应/状态/耗时/置信度/模型版本/prompt 版本 |
| FR-AI-08 | 请求脱敏 | 合同原文只存摘要与 sha256；不得把完整合同文本写日志 |
| FR-AI-09 | 人工复核 | 每个 AI 结果区都有"采纳/修改/忽略"三态；修改记 ai_feedback |
| FR-AI-10 | 批量评测 | 支持导入标注样本集跑批量评测，输出准确率/召回/误报 |
| FR-AI-11 | 模型版本管理 | `ai_model_config` 可配多个版本，按业务场景灰度（如 10% 流量用新版） |
| FR-AI-12 | 提示词版本 | 提示词模板带版本号；变更需走配置审计 |
| FR-AI-13 | 效果看板 | 按 ai_code 展示：调用量/成功率/降级率/平均耗时/采纳率/人工改判率 |
| FR-AI-14 | 数据导出 | 可导出标注样本（脱敏后）供线下训练 |
| FR-AI-15 | 成本与容量 | 记录每次调用耗时分布；图像接口并发上限（可配，默认 5） |
| FR-AI-16 | 安全 | `api_key` AES-256 加密存储；接口返回掩码；日志不含密钥 |
| FR-AI-17 | 禁公网断言 | 提供 `scripts/check-no-public-ai.sh`，CI 调用；命中即失败 |
| FR-AI-18 | 可复现 | 给定 `call_no` 能还原：模型版本 + prompt 版本 + 请求摘要 + 响应原文 |

## 6. 提示词契约（关键：不要写"帮我分析合同"）

### 6.1 合同风险分析（AI-001）

**输入组装**：
```
系统提示：你是电力/风电行业设备与工程合同的商务风险审核助手。
只输出 JSON，不输出解释。风险等级只能是 高/中/低。

任务：识别以下合同文本中的商务、技术、法律风险。重点关注：
1) 付款条件（预付款比例、质保金比例、账期）
2) 质保期与质保责任划分
3) 验收标准是否量化、是否可执行
4) 违约金/罚款条款是否有计算方式与上限
5) 知识产权与保密
6) 不可抗力与争议解决
7) 技术附件是否齐备、是否与正文冲突

行业基准（用于判断"异常"）：
- 质保金比例通常 5%—10%，低于 5% 提示
- 预付款通常 ≤30%，高于 50% 提示
- 质保期：整机厂初装 60 个月，业主技改 12 个月

输出 Schema：
{"risks":[{"type":"商务条款风险|技术风险|法律风险","level":"高|中|低",
           "description":"...","suggestion":"...","evidence":"原文片段"}]}
```

**约束**：不臆造条款；没有把握的不要报（宁可少报，不可乱报）；`evidence` 必须来自原文。

### 6.2 合同信息提取（AI-002）

**输入**：合同 PDF 全文 + 页图（用于定位）。
**输出**：12 字段 JSON + 每个字段的 `page`、`bbox`（用于左侧高亮）。
**约束**：找不到的字段返回 `null`，**不要猜**；金额统一为数字（元），不要带"万元"。

### 6.3 施工质量检测（AI-102）

**输入**：照片 + `check_type`（CABLE/INSTALL/LABEL/SAFETY）。
**输出**：`qualified` + `issues[]`（type/description/bbox/confidence）。
**约束**：只判断指定类型的检查项，不扩展；`bbox` 用相对坐标（0—1）。

### 6.4 物料模糊匹配（AI-006）

**输入**：自然语言描述（如"机舱灭火器支架"）+ 可选项目上下文。
**输出**：候选物料 Top5（编码/名称/规格/库存）。
**约束**：只从物料主数据中选，**不得编造编码**；无匹配返回空数组。

## 7. mock 数据要求

每个接口必须有可运行的 mock 样例，且样例要"像真的"（能跑通业务下游）：

| 接口 | mock 要求 |
|---|---|
| AI-001 | 返回 3 条（1 高 1 中 1 低），含 evidence |
| AI-002 | 返回完整 12 字段 + 3 条付款条件，金额与文件一致 |
| AI-006 | 返回 2 条候选物料（含真实编码与库存） |
| AI-101/102 | 返回 1 条不合格 + bbox + confidence 0.78 |
| 其他 | 返回结构合法的空/示例结果 |

**mock 开关**：`ai.mock.enabled=true`（开发默认）；生产必须为 false，且启动时校验（若生产环境开启 mock 则拒绝启动）。

## 8. 异常与边界

| 场景 | 行为 |
|---|---|
| 文件过大（>100 页合同） | 先做分段摘要再分析；提示"已按前 30 页关键条款分析" |
| 扫描件模糊/OCR 失败 | 返回 `unreadable` 提示"文件无法识别，请上传清晰版本" |
| 图像非施工场景（如截图） | 返回 `not_applicable`，不强行判定 |
| 同一文件重复提交 | 缓存命中（同 file_id + ai_code + 模型版本），返回上次结果并标 `cached=1` |
| 并发超限 | 排队（队列长度 20），超时返回"当前请求过多，请稍后" |
| 模型返回格式非法 | 视为失败 → 重试 1 次 → 仍失败 → DEGRADED |
| 业务字段已被人工修改后再调 AI | 提示"已有手工填写内容，AI 结果将放入对照区，不覆盖" |

## 9. 验收要点

1. 关闭模型服务 → 合同风险分析显示"AI 不可用"，合同仍可评审归档（全流程不阻塞）。
2. mock 模式跑通 S8 场景（合同分析→提取→补货匹配→照片检测→知识检索）。
3. AI-002 返回 12 字段，左侧 PDF 高亮位置正确（抽样 10 份，位置命中 ≥8）。
4. 置信度 0.52 的字段 → 灰色显示且无"采纳"按钮。
5. 人工改 2 个提取字段 → `ai_feedback` 有 2 条（ai_value/human_value）。
6. 同一文件重复提交 → 第二次 `cached=1`，耗时 <200ms。
7. 静态扫描无公网 AI 关键字。
8. `call_no` 可还原模型版本 + prompt 版本 + 请求摘要。
9. 效果看板显示各接口调用量/降级率/采纳率。
10. 生产环境误开 mock → 启动失败。

**声明：本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。**
