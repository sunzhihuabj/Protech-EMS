## 一、需求背景与目标（深化）

### 1.1 问题树：从"三套系统"到"四类根因"

```
现状：三套在用系统各自为政（T+ 财务 / 钉钉 审批 / 售后宝 工程）
   │
   ├─ 断点①报价→合同：报价不回流，合同重新录
   ├─ 断点②合同→生产：靠开会传，无任务化
   ├─ 断点③生产→采购：无 BOM 齐套，凭经验请购
   ├─ 断点④库房出入库：实物先走、账后补，单据滞后
   ├─ 断点⑤发货→安装：工程部不知道发了什么
   └─ 断点⑥安装→验收回款：靠催，无计划
         ↓
   四类根因（不是"系统不好用"，是四个结构性缺失）
   R1 无唯一主数据入口 → 一物多名、一码多物（BOM 审计 8,764 处缺陷）
   R2 无强制卡点     → 编码可空、建档可拖、派工可不选风场
   R3 无过程数据     → 只能在月末补写（商务部 62 条日报平均滞后 16.7 天，52% 集中补交）
   R4 无统一口径     → 同一指标各算一套，会议用于对数而非决策
         ↓
   四类后果
   数据失真（账实 92%）｜协同靠会议｜成本年底才知道｜客户响应慢
```

**设计含义**：R1—R4 各自对应一类机制，缺一不可 —— R1 → 编码引擎 + 三重查重 + 唯一建档入口；R2 → 9 处硬卡点；R3 → 扫码即记账 + 工序报工 + 卡片化；R4 → 指标口径唯一事实源（17 册）+ 九板。这解释了为什么本规格包"不能只做一半"：只做 R1 会得到干净但没人用的主数据，只做 R2 会得到一堆被绕开的弹窗。

### 1.2 "不做"的代价（只用已有数据，不编造金额）

| 现状事实 | 来源 | 不做的后果 | 可观测方式 |
|---|---|---|---|
| BOM 缺陷 8,764 处（一码多物 189、一物多码 29 组、A 级冲突 15 组影响 2,004 行） | BOM 审计 | 采购错料、库存虚高、变更失控 | 一物多码月新增（目标 0 组） |
| 呆滞 53 托盘 / 391 种 / 32,899 件 | 数据体检 | 占用库位与资金，且无人负责处置 | 呆滞金额占比（目标 ≤10%） |
| 1—8 月补货 677 行，31.9% 源于内部可控环节 | 补货分析 | 现场停工待料、加急运费 | 月度补货次数（83 → ≤35） |
| 账实相符约 92% | 盘点 | 8% 差异需靠人找，差异无人归因 | 账实相符率（→ ≥98%） |
| 商务部日报平均滞后 16.7 天，52% 集中在一天补交 | 日报统计 | 管理层看到的永远是半个月前的信息 | 卡片补录率（→ ≤5%） |
| T+ 合同号字段 100% 空置 | T+ 导出 | 财务账与业务账无法对齐，五流不一致 | 合同编码挂载率（→ 100%） |

> 本册**不估算金额损失**：源文件没有可信的单位成本与工时费率，任何金额推算都是编造。评审时若需要金额，应由财务按上表口径自行折算。

**目标之间的关系**：O1 是前提（没有编码，其余三个都算不准）；O2 是基础（账不准则成本不准）；O3 是业务价值；O4 是管理价值。**因此 O1 必须在 MVP 内 100% 达成，不接受"逐步达标"**。

### 1.4 价值假设与验证方式

| 编号 | 假设 | 若成立的表现 | 验证指标 | 失败信号（触发方案调整） |
|---|---|---|---|---|
| **H1** | 卡点少（仅 9 处）→ 业务不抵触 | 月活 ≥80 人；补录率 ≤5% | 周活跃、卡片补录率 | 上线 60 天月活 <50 → 说明卡点位置错了，不是数量问题 |
| **H2** | 扫码即记账 → 单据滞后消失 | 到货当日入库率 ≥90% | inv_transaction 与到货时间差 | <60% → 说明 PDA/网络/流程不匹配，需改作业方式而非改系统 |
| **H3** | 工序报工 → 工艺文件真被使用 | 工序报工覆盖 ≥90%；工艺覆盖率 ≥15% | 报工记录、工艺文件数/BOM 数 | 报工覆盖 <50% → 生产部仍在 Excel 报工，MES 需重做交互 |
| **H4** | 九板 + 红灯 → 会议压缩 | 协调类会议时长 −40%（估算） | 会议时长统计（手工） | 会议没减少 → 红灯卡沦为汇报工具，需重设升级规则 |
| **H5** | AI 辅助 → 合同要素录入省时 | 合同 AI 使用率 ≥80%；字段修正率 ≤20% | ai_feedback、采纳率 | 修正率 >40% → 模型不可用，回退人工并暂停推广 |

> H4 的"−40%"源自 01 册 §2.3，**本身是估算**，验证方式只能是会议时长台账。若无法采集，该指标应删除而不是保留一个无法验证的目标（见 20 册 Q-23）。

### 1.5 非目标（Not-doing）

沿用 01 册 §4.2 的 12 项不做清单，此处只补三条**容易越界**的：

| # | 非目标 | 为什么容易越界 | 边界表述 |
|---|---|---|---|
| N-1 | 不做审批流设计器 | 业务会提"我们自己画流程" | 一期审批链用配置表 + 管理界面，**不提供拖拽画布**；新增节点走配置不改代码 |

### 2.3 核心场景卡（SC-01—SC-14）

> 格式：触发 / 前置 / 主流程 / 成功判据 / 异常分支 / 相关规则。**每张卡都可直接转 UAT 脚本**。

**SC-01 报价与合同评审**
- 触发：商机确认可投或客户要求报价
- 前置：客户主体已建档；同项目已有报价需提示撞单（FR-CRM-15）
- 主流程：商机登记（FR-CRM-01）→ 跟进记录 → 转合同（FR-CRM-06）→ 起草（FR-CT-01）→ **选项目编码（BR-01）** → AI 风险分析（FR-CT-05，可跳过）→ 六要素勾选（FR-CT-12）→ 会签（FR-CT-13）→ 用印编号（FR-CT-17）
- 成功判据：评审一次通过；合同号连续；评审耗时中位 ≤1 工作日
- 异常：未选项目 → 422 + 去建档入口；AI 不可用 → 手工填不阻塞（FR-CT-10）；金额与评审版差 >5% → 重走评审（E-12）
- 相关：BR-01、FR-CRM-15、FR-CT-12/13/17

**SC-02 合同建档与交底**
- 触发：用印完成
- 前置：`filing_deadline = sign_date + 3 工作日`（FR-CT-20）
- 主流程：上传签章 PDF → AI 提取 12 字段（FR-CT-07）→ 左右分栏核对（FR-CT-08）→ 确认归档（FR-CT-09）→ 建档 26 要素（BR-02）→ 交底分发 5 人（FR-CT-13 组）→ 已阅确认
- 成功判据：档案完整率 ≥95%；交底 24h 已阅率 ≥90%
- 异常：超期未建档 → 冻结开票（BR-02）；AI 提取字段被改 → 写 ai_feedback
- 相关：BR-02、FR-CT-07/08/09/20

**SC-03 项目立项与任务派发**
- 触发：合同归档
- 前置：合同已归档且有 project_id
- 主流程：自动立项（带客户/合同/交期）→ 套用模板 6 阶段 → WBS 生成 20+ 任务 → 日期推算 → 成员分配 → 前置未完成不可开工
- 成功判据：立项 ≤1 分钟自动完成；任务逾期当日标 DELAYED
- 异常：依赖成环 → 拒绝保存（UC-PRJ-04）；无模板 → 用默认模板并提示
- 相关：FR-PRJ（05 册）、BR-03

**SC-04 BOM 编制与变更**
- 触发：技术条件确认
- 前置：A 类须选 Golden BOM；B 类须填参数；C 类标 `mbom_not_applicable`
- 主流程：勘测/技术条件 → 设计上传与审核 → EBOM 编制 → 13 条校验 → 发布 → 转 MBOM/SBOM → 变更走 ECN（BR-09：必填旧料处置）
- 成功判据：BOM 一次发布通过率 ≥90%；变更正式单率 100%
- 异常：一码多规格 A 级冲突 → 阻断发布并列出影响行数；C 类打开 MBOM 页签 → 显示"不适用"而非空表
- 相关：BR-09、C-09（BOM 二维矩阵）

**SC-05 采购与到货入库**
- 触发：齐套缺料 / 安全库存触发 / 项目专用 / 备货
- 前置：供应商已准入且资质有效；物料编码存在
- 主流程：请购（四来源）→ 合并 → 询价/价格库 → PO → 下发（通知库房/质检/生产，不含价格）→ 到货 → IQC → 扫码入库（BR：物料必须存在）→ T+ 同步 → 对账
- 成功判据：到货当日入库率 ≥90%；账实差异可定位到物料+货位
- 异常：超收 >5% 需审批；质检不合格 → 退货单；T+ 不可用 → 事务挂 PENDING_SYNC
- 相关：BR-05、C-04、E-19

**SC-06 生产报工与异常**
- 触发：工单下达、工序可开工
- 前置：前道工序 DONE；物料防错扫码通过
- 主流程：开工 → 报工（good/defect/scrap）→ 需检工序转 WAIT_QC → 检验 PASS 才 DONE → 不良锁定禁止下道 → Andon 5/15/30 分钟升级
- 成功判据：工序级可追溯；一次检验合格率 ≥98%
- 异常：扫错料 → 禁止开工 + Andon；报工数量与计划差 >10% → 必填原因
- 相关：C-11（工序级）、UC-MES-03/04/05

**SC-07 排产与插单**
- 触发：批量订单确认 / 急单插入
- 前置：MBOM 与工序路线就绪；产能日历已配
- 主流程：齐套检查 → L1 规则排产 → L2 有限产能 → 排产甘特 → 发布 → 插单模拟（输出受影响订单 + 最早可承诺交期）
- 成功判据：同资源不重叠；排产达成率 ≥85%
- 异常：无可行解 → 返回冲突报告（哪些资源/物料卡住），不阻断
- 相关：C-11、UC-MES-09/10

**SC-08 发货与派工**
- 触发：齐套完成或链主批准非齐套发货
- 前置：项目编码存在（BR-03）；派工必须选风场（BR-04）
- 主流程：发货申请 → 齐套校验（不足需链主审批并计数）→ 扫码出库 → 生成派工单（物料=发货明细）→ 班组接单
- 成功判据：派工挂载率 ≥95%；非齐套发货次数可统计
- 异常：未选风场 → 弹窗二选一（补选/申请新建）；拆挂台数不符 → 拒绝
- 相关：BR-03、BR-04、E-05

**SC-09 现场施工与整改**
- 触发：班组进场
- 前置：人员保险有效；账号 ACTIVE；仅小程序（BR-08）
- 主流程：看水印图纸（BR-07）→ 填施工日志 → 拍照（原图不留）→ AI 质量检测（可跳过）→ 发现问题开整改单 → 整改 → 复核 → 关闭
- 成功判据：离线 10 条同步无重；整改超期自动升级
- 异常：断网 → 本地队列 + "待同步 N 条"；冲突 → 转草稿；保险过期 → 拒绝授权
- 相关：BR-07、BR-08、E-13

**SC-10 验收、开票与回款**
- 触发：销项 100% 且整改关闭
- 前置：无未闭环整改

- 异常：有未关闭整改 → 验收按钮置灰并列明；超期未建档 → 开票 422
- 相关：BR-02、E-03

**SC-11 成本归集与看板过堂**

**SC-12 主数据建档与查重**

**SC-14 AI 辅助与人工复核**

## 三、功能清单与优先级

### 3.1 方法与参数定义

- **MoSCoW**：Must（MVP 必须）/ Should（二期）/ Could（三期）/ Won't（本期不做，见 1.5）
- **RICE**：`(Reach × Impact × Confidence) ÷ Effort`
  - Reach：每月受影响人次（按 121 人组织与业务频次估）
  - Impact：3 极大 / 2 大 / 1 中 / 0.5 小 / 0.25 微小
  - Confidence：100% 有数据 / 80% 有依据 / 50% 推测
  - Effort：人日（取 18 册 §4.1 测算值）
- **排序边界**：RICE 只用于**同层内排序**，不用于砍"必备型"能力（见 3.3 校正说明）

1. 全部在**服务端**校验，前端只做提示；
2. 统一错误码 `5001` + `blockCode`，便于统计"制度被绕过"；
3. 拦截必须**给出下一步**（去建档/去补选/去补签），否则业务会绕开；
4. 不允许"管理员可关闭卡点"这种开关——有例外单机制即可，开关等于没有卡点。

### 4.2 边界条件矩阵（8 类）

| 类别 | 典型场景 | 期望行为 | 归属 |
|---|---|---|---|
| **空/无数据** | 列表无数据；未配置字典；项目无成员 | 显示空状态 + 主行动按钮；不显示"暂无数据"了事 | 全部列表页 |
| **超限** | 金额超 `DECIMAL(18,2)`；BOM 行 >5,000；附件 >500MB；导入 >5 万行；分页 >200 | 前端预校验 + 服务端硬限；给出明确上限值 | FR-INV/FR-PLM/导入框架 |

| **时间** | 跨月签合同（归属按 `sign_date`）；用印遇节假日顺延；跨年编号；时区 | 归属按业务日期不按录入日；节假日表可配；编号按自然年重置 | 17 册 §1、FR-CT-20 |

### 4.3 并发、幂等与补偿

| 机制 | 规则 | 落点 |
|---|---|---|
| 乐观锁 | 所有单据带 `version`，更新影响行数 0 → 409 + 当前版本 | 16 册 §4.4 |
| 幂等键 | `业务主键 + 渠道流水号`；库存事务/导入/推送必带；重复请求返回首次结果 | 14 册 §8 |
| 重试 | T+ 3 次指数退避（5s/25s/125s）；AI 重试 1 次；文件转换重试 2 次 | 14 册 §8、15 册 |
| 补偿 | 每日 23:00 对账；差异入 `int_reconcile_diff`；人工可重试/导出 | 00 册 C-04 |
| 分布式锁 | job-worker 多副本用 ShedLock | 16 册 §2.1 |

### 4.4 跨主体与第三方隔离边界

| 边界 | 规则 | 反例（必须拒绝） |
|---|---|---|
| 法人主体 | 物料/库存/合同按 `legal_entity` 强隔离；跨主体调拨需双人确认 | 特固兰物料在普若泰克仓扫码出库（UC-INV-05） |

### 4.5 规则治理

- **新增卡点 = L4**（见 3.5），且必须同时给出"错误提示文案 + 下一步链接 + 例外路径"；
- **修改阈值 = L2**，走配置变更单；
- **删除卡点 = L4**，需说明"为什么制度已能保证"；
- 每季度复盘：拦截次数 Top3 的卡点，检查是"制度有效"还是"设计太糙"。

## 十、附录

### 10.1 术语增量（12 条）

| 术语 | 定义 | 易混点 |
|---|---|---|
| 边界条件 | 系统在空/超限/重复/并发/越权等极端输入下的既定行为 | 不是"异常处理"，异常处理是运行时错误 |
| 例外单 | 硬卡点的唯一合法绕过凭据，需审批并计入例外率 | 不是"管理员开关" |
| 口径 owner | 对某指标公式与统计范围负唯一责任的角色 | 不是"看板维护人" |
| 四元组留痕 | 模型版本/提示版本/知识版本/规则版本 | 只记模型版本不够 |
| 权责空白 | 规格未指定责任人但业务必须有人负责的环节 | 与"待确认"不同，后者是信息缺失 |
| 必备型/期望型/兴奋型 | Kano 分类，用于修正 RICE 的失真 | 不是优先级同义词 |
| 带条件上线 | 有一般缺陷但可上线，附 30 天清零承诺 | 不是"先上线再说" |
| 分期验收 | 依赖未就绪时，将该能力标"未启用"其余照常验收 | 不是降低标准 |
| 幂等键 | 业务主键 + 渠道流水号，保证重复请求不重复入账 | 不是"防重复点击" |
| 齐套率 | `fulfill_rate=100%` 的订单 ÷ 在手订单 | 不是"缺料行数占比" |
| 补录率 | `is_backfill=1` 的卡片或报工 ÷ 总数 | 反映制度是否被绕过 |
| 例外率 | 走例外单的卡点数 ÷ 该卡点拦截总数 | 与补录率同为"制度健康度"指标 |
