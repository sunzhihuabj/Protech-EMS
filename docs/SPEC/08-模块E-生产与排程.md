# 08 · 模块 E：生产与排程（D06 + D07）

> 覆盖断点③生产→采购的下半段。本模块是 00 册 C-11 裁决的结果：**采用工序级管理，不做"最小字段"降级**。
> 理由：生产部 20 人是全公司第二大部门；BOM 审计发现工艺落线缺口（导轨 0%）的根因是"工艺文件不是随产品强制产出物"，只有把工序搬进系统、报工必须过工序，工艺文件才真正被使用。
> 规则编号 `FR-MES-nn` / `FR-APS-nn`。

---

## 1. 模块目标

| 目标 | 定义 | 反面（现状） |
|---|---|---|
| 工序可追 | 每道工序独立开工/报工/检验，不良品锁定不流入下道 | 整个工单一个状态，不知卡在哪道工序 |
| 进度透明 | 车间看板实时显示计划/实际产量、在制数量 | 靠班组长口头汇报 |
| 异常快响 | Andon 一键报警，超时自动升级 | 缺料停线半小时才有人知道 |
| 报工即成本 | 报工工时直接归集人工成本 | 月底凭记忆估工时 |
| 排产有据 | 有限产能 + 齐套检查 + 插单模拟 | 靠计划员拍脑袋排 |

## 2. 生产订单

### 2.1 三种订单类型

| 类型 | 触发 | 关联 BOM | 数量 | 典型场景 |
|---|---|---|---|---|
| **样机** | 项目任务完成 EBOM 输出后，技术经理发起 | EBOM | 1—3 台 | 新产品首台验证 |
| **批量** | 正式 MBOM 发布后，项目经理或生产主管创建 | MBOM | 按订单 | 标准产品量产 |
| **临时补货** | 一键补货或售后工单触发 | 临时 BOM（可从 EBOM 复制改） | 少量 | 现场缺件、维修换件 |

### 2.2 功能需求

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-MES-01 | 创建生产订单 | 编号 `MO-{YYYYMM}-{4位}`；必填：项目（BR-03）、类型、BOM、计划数量、计划起止 |
| FR-MES-02 | BOM 校验 | 样机只能选 EBOM；批量只能选已发布 MBOM；临时可选任意已发布版本 |
| FR-MES-03 | 工序路由自动生成 | 按 `pcs_route` 生成工序工单序列；也可由生产主管手工调整（加/删/改序） |

| FR-MES-06 | 在制品监控 | 看板展示每个订单的工序进度（哪些已完成、哪个在加工、在制数量） |

## 4. 排程（APS）

### 4.1 排产能力分级（重要：一期不追求最优算法）

| 级别 | 方法 | 一期是否做 | 说明 |
|---|---|---|---|
| L1 规则排产 | 按交期优先级 + 瓶颈工序顺序（正排/倒排） | **✔ 必做** | 可解释、可人工干预，先让计划员用起来 |
| L2 有限产能排产 | 考虑设备/人员/模具日历，避免资源冲突 | **✔ 必做** | 甘特图可视化，人工可拖 |
| L3 遗传算法优化 | GA + TOC，多目标（交期/换线/利用率） | ○ 二期 | 一期留接口，不实现算法；先积累 3 个月排产数据 |

> **裁决说明**：A 的方案要求一期就上遗传算法。但遗传算法需要 ① 准确的产能与换线时间数据 ② 稳定的工序路线 ③ 可评估的目标函数——这三样在第一期都不具备。先做 L1/L2，让计划员把数据喂准，二期再上算法，这是更稳的路径。**若强行一期上 GA，结果会是"算出来的排产没人信"**。

### 4.2 功能需求

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-APS-01 | 排产输入 | 待排产生产订单（按优先级/交期排序）、产能日历、工序路线、标准工时 |
| FR-APS-02 | 产能维护 | 资源（设备/人员/模具）日产能、班次日历、维保停机时间 |
| FR-APS-03 | 规则排产（L1） | 按 ① 交期最早优先 ② 同产品合并减少换线 ③ 瓶颈工序优先 排序；输出工序级计划起止 |
| FR-APS-04 | 有限产能（L2） | 同一资源同一时间只能一个任务；考虑换线时间、维保时间 |
| FR-APS-05 | 齐套检查前置 | 排产前自动跑齐套；缺料订单给出"最早可开工日"（按预计到货日） |
| FR-APS-06 | 排产结果 | 生成 `aps_schedule` + `aps_schedule_detail`；状态"计算中→已发布" |
| FR-APS-07 | 排产甘特 | 按资源（设备/工作中心）横向展示任务条；拖拽调整；冲突高亮 |
| FR-APS-08 | 手工调整 | 支持拖拽、拆分、锁定（`is_locked`，重排时不动） |
| FR-APS-09 | 重排 | 支持全量重排/局部重排（只排某段区间）；重排前提示影响 |
| FR-APS-10 | 插单模拟 | 急单插入 → 模拟对现有订单交期的影响 → 输出受影响订单清单 + 最早可承诺交期 |
| FR-APS-11 | CTP/ATP | 接单时按当前负荷算可承诺交期：ATP = 现有可用产能；CTP = 含可扩产能 |
| FR-APS-12 | 无解处理 | 返回冲突报告（哪个资源/物料卡住），建议放宽条件（加班/外协/延期），不返回空 |
| FR-APS-13 | 排产版本 | 每次排产生成版本号；可对比两版差异；可回滚到上一版 |
| FR-APS-14 | 算法接口预留 | `ScheduleAlgorithm` 接口：`RULE`（默认）/`GA`（二期）；配置切换 |
| FR-APS-15 | 多项目协调 | 多项目共享产能时按优先级/交期/毛利排序；优先级可配 |
| FR-APS-16 | 排产看板 | 产能负荷率、瓶颈资源、延期风险订单 Top10 |

## 5. 业务规则

| 编号 | 规则 |
|---|---|
| BR-MES-01 | 前道工序未 DONE，后道不得开工（按钮级阻断，不是提示） |
| BR-MES-02 | 报工数量合计必须等于计划数量；不等必须填差异原因 |
| BR-MES-03 | 不良品扫码即锁定，未走 MRB 不得流入下道 |
| BR-MES-04 | 关键工序未扫码确认物料，不得开工 |
| BR-MES-05 | 工序工时以系统记录为准，不以人工填报为准（填报仅作参考，差异 >20% 提示） |
| BR-MES-06 | 生产订单关闭需全部工序 DONE + OQC PASS + 入库完成 |
| BR-APS-01 | 同一资源同一时间不得排两个任务（硬约束） |
| BR-APS-02 | 缺料订单可排产，但必须显示"物料未齐"标记与最早可开工日 |
| BR-APS-03 | 已锁定（`is_locked=1`）的排产明细不被重排覆盖 |
| BR-APS-04 | 排产版本发布后，生产订单的计划日期同步更新；未发布不影响 |

## 6. 异常处理

| 场景 | 行为 |
|---|---|
| 报工数量与计划不符 | 允许提交但必须填原因；差异 >5% 提示主管复核 |
| 工序无工作中心 | 拒绝创建，提示先维护工艺路线 |
| 排产无可行解 | 返回冲突报告 + 建议（加班/外协/延期）；不静默失败 |
| 插单导致 8 个订单延期 | 输出受影响清单（订单/原交期/新交期/延期天数），由商务决定是否接单 |
| Andon 无人响应 | 三级升级；30 分钟未解决自动通知生产部经理 + 进红灯卡 |
| 报工后发现报错 | 允许红冲重报（生成反向记录），不允许直接改历史 |
| 设备临时故障 | 手动把该资源标记"停机"，重排时跳过；恢复后改回 |
| 小程序断网报工 | 本地队列 → 联网同步（幂等）；冲突标记人工处理 |

## 7. 验收要点

1. 创建批量生产订单 → 按 MBOM 自动生成 5 道工序（钣金→焊接→喷涂→组装→调试），工序依赖串行。
2. 前道未完工 → 后道"开工"按钮不可用。
3. 关键工序扫错物料 → 禁止开工 + Andon 报警 + 防错记录写入。
4. 报工 good=8 defect=1 scrap=1 planned=10 → 通过；planned=12 → 提示差异需填原因。
5. need_inspection 工序完工 → 状态 WAIT_QC + 质量部收到检验任务；PASS 后工序 DONE。
6. 报工 2 小时 → `cost_item` 生成 LABOR 成本 = 2 × 费率。
7. Andon 触发 5 分钟未响应 → 升级班组长；15 分钟 → 生产主管。
8. 排产 10 个订单 → 同一资源无时间重叠；缺料订单标"物料未齐"并给出最早开工日。
9. 插单急单 → 输出受影响订单清单与最早可承诺交期。
10. 重排两次 → 版本可对比，可回滚。

**声明：本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。**
