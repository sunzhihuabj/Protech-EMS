# 14 · 集成规格（D15）

> 一条总原则：**所有外部系统都走适配器，先能跑（MOCK/FILE），再好用（API）。**
> 理由很实在：T+ 开放接口、微信小程序资质、快递100 采购、OnlyOffice 部署，这四件事都不由开发决定。若把主流程绑死在任何一条 API 上，项目就会卡在"等对方"。
> 规则编号 `FR-INT-nn`。

---

## 1. 适配器架构（唯一实现方式）

```java
public interface IntegrationAdapter {
    String getCode();                       // T_PLUS / WECHAT / EXPRESS / ONLYOFFICE / DINGTALK
    Mode getMode();                         // API / FILE / MOCK
    HealthResult ping();

    // 拉取
    default List<ExtOrder>   pullOrders(LocalDateTime since)   { throw new UnsupportedOperationException(); }
    default List<ExtStock>   pullStock(LocalDateTime since)    { throw new UnsupportedOperationException(); }
    default List<ExtExpress> pullTracking(String trackingNo)   { throw new UnsupportedOperationException(); }

    // 推送
    default PushResult pushStockTxn(StockTxnPayload p);
    default PushResult pushPurchase(PurchasePayload p);
    default PushResult pushMessage(MessagePayload p);

    // 对账
    default ReconcileResult reconcile(LocalDate date);
}
```

**四条硬约束**：

| # | 约束 |
|---|---|
| 1 | 业务代码**不得**直接调用任何外部 SDK；只依赖 `IntegrationAdapter` 接口 |
| 2 | 每个适配器必须实现 `MOCK` 模式（返回固定样例），保证无外部依赖也能跑通全流程与自动化测试 |
| 3 | 所有推送走 `int_outbox` 队列：业务事务内只写 outbox（同库事务），由 job-worker 发送 |
| 4 | 失败指数退避重试 3 次（1min/5min/30min），仍失败标 FAILED 并告警；界面可手动重试、可批量重试 |

## 2. T+ 集成（最关键）

### 2.1 数据流向与权威边界

| 方向 | 数据 | 频率 | 一期方式 | 二期方式 |
|---|---|---|---|---|
| T+ → 系统 | 销售订单（新增/变更） | 每日 07:00 + 手动 | 文件（T+ 导出 xlsx → 上传解析） | API |
| T+ → 系统 | 存货现存量（基线/校准） | 上线 1 次 + 每月 | 文件 | API |
| T+ → 系统 | 客户档案（仅比对） | 每月 | 文件 | API |
| 系统 → T+ | 出入库单据（其他入库单/其他出库单） | 每日（扫码数据日清日结） | 导出标准 Excel 给财务录入 | API |
| 系统 → T+ | 合同号回填清单 | 每日 | 导出清单，财务在 T+ 补录 | 同左（T+ 字段须手工） |

> **不做**：凭证生成、总账、财务报表取数。T+ 是唯一财务核算系统。
> **不做**：本地权威库存数量表（见 00 册 C-04 与 07 册 §1）。

### 2.2 销售订单字段映射（T+ 导出 → `scm`/`prj` 侧）

| T+ 列 | 系统字段 | 转换规则 |
|---|---|---|
| 单据编号 | `t_plus_order_no` | 去空格；作为幂等键 |
| 单据日期 | `order_date` | 兼容 `YYYY-MM-DD` / `YYYY/M/D` |
| 客户 | `customer_name_raw` | 与主体库模糊匹配（≥0.8 自动，0.6—0.8 待确认，<0.6 新建待归类） |
| 业务员 | `sales_owner_name` | 匹配用户；空则计入"必填缺失"报表 |
| 部门 | `dept_name` | 匹配部门 |
| 存货编码 | `material_code` | 匹配物料；不存在进"待建物料"清单 |
| 存货名称 | `material_name` | 与主数据比对，不一致记 WARN |
| 规格型号 | `spec` | 同上 |
| 数量 | `qty` | DECIMAL(14,3) |
| 计量单位 | `unit` | 映射到 E-20（只/根/把→个或米，映射表可配） |
| 单价/金额 | `unit_price` / `amount` | **元 → DECIMAL(18,2)**；**不使用浮点** |
| 交货日期 | `delivery_date` | ≤单据日期 → 标 `abnormal_lead_time=1` 并计入报表 |
| 仓库名称 | `warehouse_code` | 映射到 `md_location` 所属仓库 |
| 合同号 | `t_plus_contract_no` | 空 → 进"待回填"清单 |
| 送货地址 | `delivery_address` | 原文保留；尝试提取风场线索（建档提示用） |
| 备注 | `remark` | 原文 |

**导入校验（干跑阶段全查，任一行失败整批不落库）**：
1. 单号非空且库内不存在（已存在 → 幂等更新，不算失败）；
2. 数量 >0；
3. 物料存在（不存在标"待建物料"，允许"跳过该行"继续）；
4. 客户可匹配或可新建；
5. 金额 = 数量 × 单价（误差 ≤1 分），不等则 WARN 并以金额为准。

### 2.3 出入库单据导出模板（系统 → T+）

列：`单据类型, 单据日期, 仓库, 存货编码, 存货名称, 规格型号, 数量, 单位, 项目编码, 合同号, 来源单号, 备注`

- 单据类型：`其他入库单` / `其他出库单`；
- 每日导出一份：`PBC-TPLUS-{YYYYMMDD}-{序号}.xlsx`；
- 导出后标 `exported_at` 避免重复；红冲另出负数单据；
- 财务录入后回填 T+ 单据号，形成双向对照。

### 2.4 库存同步与对账

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-INT-01 | 库存缓存刷新 | 定时 5 分钟拉 T+ 现存量 → 写 `inv_stock_cache`；用户手动刷新可强制拉 |
| FR-INT-02 | 缓存失效降级 | T+ 不可用 → 缓存超时仍返回旧值并标"数据可能过期（截至 HH:mm）"；不返回空 |
| FR-INT-03 | 事务推送 | 每次扫码出入库 → 写 outbox → 调 T+ → 成功回写 `t_plus_voucher_no` |
| FR-INT-04 | 推送失败 | 退避重试 3 次 → EXCEPTION → "待人工处理"页可重试/导出 |
| FR-INT-05 | 每日对账 | 23:00 生成：本地事务 vs T+ 流水；差异入 `inv_reconcile` + `int_reconcile_diff` |
| FR-INT-06 | 对账三列 | 本月事务笔数 / 已导出笔数 / 财务已入账笔数 |
| FR-INT-07 | 差异定位 | 精确到物料+货位+批次；状态 OPEN/CONFIRMED/CLOSED；不自动调账 |
| FR-INT-08 | 异常率告警 | 差异率 >0.5% 或单笔 >1 万元 → 推送财务与仓储负责人 |

### 2.5 文件适配器目录约定

```
{DATA_ROOT}/tplus/inbox/      财务放导出文件（SO_YYYYMMDD.xlsx / STOCK_YYYYMMDD.xlsx）
{DATA_ROOT}/tplus/archive/    解析成功后移入（按日期分子目录）
{DATA_ROOT}/tplus/error/      解析失败移入 + 生成 .err.txt
{DATA_ROOT}/pbc-outbox/       系统导出给财务的文件
```
Worker 每 10 分钟扫 inbox（可配）。成功才移 archive，失败不移（防丢数据）。

## 3. 微信小程序集成

| 能力 | 说明 |
|---|---|
| 登录 | `wx.login` 拿 code → 后端换 openid → 绑定系统账号（首次需账号密码绑定） |
| 模板消息 | 任务分配/整改通知/审批结果；需用户订阅 |
| 文件预览 | `wx.downloadFile` + `wx.openDocument`——**仅限已发布 PDF 预览件**，禁保存原文件 |
| 拍照 | `wx.chooseMedia`（压缩前原图） → 上传 → 服务端合成水印 |
| 定位 | `wx.getLocation`（打卡用）；偏离 >50km 提示确认 |
| 禁止 | 禁用 `wx.saveImageToPhotosAlbum`、打印相关 API、`wx.shareFileMessage` 转发文件 |

**端限制实现**：登录接口校验 `user_type` + 请求来源（`X-Client: MP`）。R17 无该头 → 403。

**离线**：`wx.setStorageSync` 队列（上限 10MB/项，总 200MB）；同步带 `cachedVersion` 做冲突检测。

## 4. OnlyOffice 集成

| 项 | 说明 |
|---|---|
| 部署 | 私有化社区版，独立容器；通过 `document-server` 域名内网访问 |
| 用途 | 工艺文件（Word/Excel）在线编辑；合同/技术文件只读预览 |
| 回调 | 保存回调 → 后端拉取新文件 → 存为新版本 → 触发 AI 生成变更描述（AI-007） |
| 权限 | 只有 `file:edit` 可编辑；其他只读；编辑时锁定（他人只读打开） |
| 降级 | 服务不可用 → 在线编辑按钮置灰，提示"在线编辑暂不可用，请下载模板后上传" |
| 安全 | 文档 key 用哈希（不含真实路径）；不回传原始文件 URL 给前端 |

## 7. 钉钉旁路（一期只做消息）

| 项 | 一期 | 说明 |
|---|---|---|
| 群机器人 Webhook | ✔ | 单向消息（红灯升级/跨部门挂卡/合同超期/安全件超时/指标跌破） |
| 工作通知 | ○ 二期 | 需自建应用 |
| 免登 | ○ 二期 | 一期用账号密码 |
| 审批 | **不做** | **关键决策**：源文件的病根就是"审批单与业务单据两张皮"，若把审批搬回钉钉等于重新引入问题。审批在系统内完成，钉钉只做消息通道 |

**消息格式示例**：
```json
{"msgtype":"markdown","markdown":{"title":"红灯升级提醒","text":
"### 红灯卡已升级（超 3 天）\n\n**卡片**：远景 P-0896 自消组件备货\n**责任人**：@采购-张\n**卡点**：缺 2 项外购件，供应商未到货\n**已挂起**：4 天\n\n[打开看板](https://pbc.example.com/kb/card/123)"}}
```

**触发场景**：① 红灯升级；② 跨部门挂卡；③ 48h 未响应；④ 合同建档超期；⑤ 补货安全件超时；⑥ 指标跌破红线（日汇总一次）。

## 8. 幂等、重试与一致性

| 场景 | 幂等键 | 重试 | 一致性 |
|---|---|---|---|
| 文件导入 | `文件内容哈希 + 模块` | 不自动（人工重传） | 单事务全成功/全回滚 |
| 库存事务 | `来源单号+行号+动作` | 客户端可重试 | 强一致（同库事务） |
| T+ 单据推送 | `txn_no` | 退避 3 次 | 最终一致；失败进人工 |
| 微信模板消息 | `message_id`（业务事件生成） | 3 次 | 允许丢失（非关键） |
| OnlyOffice 回调 | `document_key + version` | 3 次 | 最终一致 |
| 快递100 查询 | `tracking_no + date` | 3 次 | 允许失败（可手工） |
| 卡片升级扫描 | `card_id + 级别` | 定时任务天然幂等 | 强一致 |

## 9. 导入导出通用规格

### 9.1 导入五步

| 步 | 动作 | 系统行为 |
|---|---|---|
| 1 | 下载模板 | 按模块生成 xlsx（表头 + 示例行 + 字段说明 + 枚举可选值） |
| 2 | 上传 | 校验扩展名/大小/表头版本 |
| 3 | **干跑校验** | 全行校验，**不落库**；输出成功/警告/失败三类计数 |
| 4 | 查看报告 | 行号+列名+原值+原因+建议；可导出；可在线修正重传 |
| 5 | 确认导入 | 单事务落库（全成功或全回滚）；生成批次号；可回滚（仅限无下游引用） |

### 9.2 回滚条件

- 该批次创建的单据**尚无下游引用**（如导入的请购未被转采购）；
- 回滚为软删除 + 审计；
- 已产生库存事务的批次**不可回滚**（只能红冲）。

### 9.3 导出规格

| 项 | 规定 |
|---|---|
| 格式 | xlsx（主）/ csv（大数据量） |
| 上限 | 单次 50,000 行；超出提示分批或后台导出 |
| 权限 | 按数据范围过滤；金额列按角色脱敏 |
| 留痕 | 记导出人/时间/模块/筛选条件/行数/字段集 |
| 文件名 | `{模块}-{筛选摘要}-{YYYYMMDDHHmm}.xlsx` |

### 9.4 必须提供的导入模板（14 个）

1. 客户主体库（含集团归并）｜2. 风场库｜3. 项目档案（含别名列）｜4. 物料主数据（含新旧码）｜5. BOM 行｜6. T+ 销售订单｜7. T+ 存货期初｜8. 供应商｜9. 货位｜10. 合同存量（关键 12 项）｜11. 期初应收｜12. 员工与部门｜13. 工序路线与工时｜14. 检验标准

## 10. 降级矩阵（哪条腿断了系统还能跑）

| 断掉的依赖 | 影响 | 降级方案 | 阻塞主流程？ |
|---|---|---|---|
| T+ 无接口 | 订单手工导入；出入库导出给财务 | 文件适配器（已内置）；订单也可系统内直接建 | 否 |
| T+ 导出也拿不到 | 无库存基线 | 手工盘点建期初 + 系统内建订单 | 否 |
| 微信小程序资质未下 | 现场作业无移动端 | H5 响应式页（内部员工）；第三方作业延后 | 否（但第三方功能延后） |
| 快递100 未采购 | 无自动轨迹 | 手工录入 | 否 |
| OnlyOffice 未部署 | 无在线编辑 | 下载模板 → 本地编辑 → 上传 | 否 |
| AI 模型未就绪 | 无 AI 能力 | mock + 人工模式 | 否 |
| 钉钉机器人未配 | 无群消息 | 站内信 + 邮件 + 会议投屏 | 否 |
| 文件服务器不可用 | 无附件 | **阻塞**（附件是刚需）；需 4h 内恢复 | **是** |
| 云/本地服务器不可用 | 全部停 | 备份恢复到备用机（RTO ≤4h）+ 纸质应急单 | **是**（短时可容忍） |

> **降级原则**：任何外部依赖缺失，系统必须仍能在"纯本地模式"下跑通 S1 主链路（商机→合同→项目→BOM→库存→生产→发货→派工→验收→回款）。这条作为架构验收项。

## 11. 验收要点

1. 全部适配器设 MOCK → S1 主链路完整跑通，无外部依赖阻塞。
2. 导入 500 行 T+ 订单：干跑报 3 行错误（物料不存在），修正后全量导入成功，批次可查。
3. 同一文件导入 2 次 → 订单不重复（幂等更新）。
4. 推送 T+ 失败 3 次 → 进"待人工处理"，可重试、可导出。
5. T+ 挂掉时库存查询返回旧值 + "数据可能过期"提示，不返回空。
6. 每日对账能定位到"某物料某货位差 12 件"。
7. 小程序 R17 登录成功，PC 登录 403。
8. OnlyOffice 停掉 → 编辑按钮置灰，上传下载仍可用。
9. 钉钉未配 → 升级消息降级为站内信，不报错。
10. 静态检查：业务代码中无外部 SDK 直接调用（只依赖接口）。
