# 15 · 非功能、部署与安全（D16）

> 本册回答三个问题：**跑多快、怎么部署、出事怎么办。**
> 性能基线按 00 册 C-03 裁决：**200 在线 / 100 QPS，容量按 300 / 150 留余量**（不按 1000 设计）。

---

## 1. 性能指标

### 1.1 响应时间（P95）

| 场景 | 要求 | 说明 |
|---|---|---|
| 普通页面加载 | ≤500ms | 首屏可交互 |
| 表单提交（单表） | ≤500ms | 不含附件上传 |
| 列表查询（带筛选+分页） | ≤1s | 1 万行内，服务端分页 |
| 复杂报表/看板 | ≤3s | 含多指标聚合 |
| 单据保存（含校验） | ≤1s | 合同 26 要素 |
| 排产计算（L1/L2） | ≤30s | 100 个订单、20 个资源 |
| 齐套检查 | ≤5s | 500 行 BOM |
| 文件上传请求本身 | ≤1s | 500MB，水印转换异步 |
| 文件下载（含水印生成） | ≤5s | 100 页 PDF，已缓存则 ≤1s |
| AI 调用 | 30s / 图像 20s | 超时降级 |
| 扫码提交 | ≤800ms | 移动端 4G |
| 看板首屏 | ≤2s | 5 指标 + 50 卡片 |

### 1.2 并发与容量

| 项 | 设计值 | 余量 | 说明 |
|---|---|---|---|
| 在线用户 | 200 | 300 | 全公司 121 人 + 第三方，峰值 90% 同时在线 |
| 并发请求 | 100 QPS | 150 | 按每用户 0.5 QPS 估 |
| 数据库连接池 | 50 | — | HikariCP，max=50 / min=10 |
| Redis 连接 | 100 | — | Lettuce 共享连接 |
| 单据并发编辑 | 乐观锁 | — | `version` 字段，冲突返回 409 |

### 1.3 容量估算

| 数据 | 首年 | 三年 | 单条大小 |
|---|---|---|---|
| 业务单据 | ~50 万行 | ~200 万行 | <2KB |
| 库存事务 | ~8 万 | ~30 万 | <1KB |
| 操作日志 | ~80 万 | ~300 万 | ~1KB（JSON） |
| SPC 数据 | ~5 万 | ~20 万 | <500B |

**数据库初始配置**：4 核 16GB，SSD 200GB；三年数据量 <50GB，无需分库分表（仅日志表按月分区）。

## 2. 可用性与容灾

| 指标 | 要求 |
|---|---|
| 月度可用性 | ≥99.5%（月故障 ≤3.6h） |
| 计划停机 | 每月 ≤1 次，安排在非工作时间（20:00 后） |
| RPO | ≤1h（每小时增量备份） |
| RTO | ≤4h（含恢复验证） |
| 数据保留 | 业务数据永久；日志 2 年热 + 归档；附件 10 年 |

### 2.1 备份策略（3-2-1 原则）

| 层 | 内容 | 频率 | 保留 |
|---|---|---|---|
| 数据库全量 | `mysqldump` 或 XtraBackup | 每日 02:00 | 30 天 |
| 数据库增量 | binlog 归档 | 每小时 | 7 天 |
| 附件 | `rsync` 到备份盘 | 每日 03:00 | 30 天 |
| 异地/离线 | 每周一次打包到移动硬盘或对象存储 | 每周日 | 12 周 |
| 恢复演练 | 每半年一次 | — | 记录留档 |

**硬要求**：备份文件必须**加密**（含客户合同、成本数据）；恢复演练必须真的恢复到独立环境并跑一遍主链路。

### 2.2 故障处置

| 故障 | 影响 | 处置 | 目标恢复 |
|---|---|---|---|
| 应用进程崩溃 | 全部不可用 | 容器自动重启（`restart: always`）；健康检查失败 3 次重启 | ≤5 分钟 |
| 数据库崩溃 | 全部不可用 | 从最近全量 + binlog 恢复到故障前 | ≤4 小时 |
| 数据库磁盘满 | 写入失败 | 告警 → 清理日志分区 → 扩容 | ≤1 小时 |
| 文件服务器不可用 | 附件不可用（阻塞） | 切备用挂载点；从备份恢复 | ≤4 小时 |
| Redis 不可用 | 会话与缓存失效 | 降级：会话改 JWT 校验（无黑名单），缓存直查库 | ≤10 分钟 |
| AI 网关不可用 | AI 功能降级 | 自动降级为人工模式 | 不影响主流程 |
| T+ 接口不可用 | 库存无法同步 | 事务挂起队列，恢复后批量重试 | 不影响业务录入 |
| 网络中断 | 内网可继续，外网（小程序）不可用 | 小程序转离线模式 | — |

## 3. 部署架构

### 3.1 四个进程（按 00 册 C-02）

| 进程 | 职责 | 资源建议 | 副本 |
|---|---|---|---|
| `projlife-app` | 主应用（模块化单体，14 个 Maven 模块） | 4C 8G | 1（扩容可到 2） |
| `projlife-ai-gateway` | AI 网关（唯一访问内网模型） | 2C 4G | 1 |
| `projlife-file-service` | 文件转换/水印/OnlyOffice 回调 | 2C 4G | 1 |
| `projlife-job-worker` | 定时任务（提醒/升级/指标/对账/预警） | 2C 4G | 1（多副本需分布式锁） |
| MySQL/GreatDB | 主数据库 | 4C 16G + SSD 200G | 1（主从可选） |
| Redis | 会话/缓存/锁 | 2C 4G | 1 |
| RabbitMQ | 异步任务/事件 | 2C 4G | 1 |
| Nginx | 反向代理/HTTPS/静态资源 | 1C 2G | 1 |
| OnlyOffice | 文档服务 | 4C 8G | 1 |
| 文件服务器 | NAS/SMB | 按容量 | 1 |

**最小生产配置**：单台 8C 32G 服务器 + NAS（All-in-One，Docker Compose）。这是 121 人公司的合理起点。
**扩容触发**：在线 >250 持续一周，或 CPU 持续 >70%，则应用无状态化 → 双节点 + Nginx 分流 + Session 外置。

### 3.2 部署清单（docker-compose 片段）

```yaml
services:
  app:
    image: projlife/app:${VERSION}
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DB_URL=jdbc:mysql://db:3306/projlife?useUnicode=true&characterEncoding=utf8mb4
      - REDIS_HOST=redis
      - MQ_HOST=rabbitmq
      - FILE_ROOT=/data/files
      - AI_GATEWAY_URL=http://ai-gateway:9100
    volumes:
      - /data/files:/data/files
    depends_on: [db, redis, rabbitmq]
    restart: always
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/actuator/health"]
      interval: 30s
      retries: 3
```

### 3.3 环境划分

| 环境 | 用途 | 数据 |
|---|---|---|
| dev | 开发自测 | mock 数据，可随意重置 |
| test | 集成测试/自动化 | 脱敏的样本数据 |
| uat | 用户验收 | 从生产脱敏抽样 |
| prod | 生产 | 真实数据，**禁止外网访问** |

**硬要求**：`dev/test` 不得连生产库；生产配置文件中不得出现 mock 开关为 true（启动时校验，见 13 册 §7）。

## 4. 安全要求

### 4.1 认证与会话

| 项 | 要求 |
|---|---|
| 密码强度 | ≥8 位，含大小写+数字；禁止常见弱密码（内置字典） |
| 密码存储 | BCrypt（cost=10） |
| 首登改密 | `must_change_pwd=1` 时除改密页外全部 302 |
| 密码有效期 | 90 天提示更换（不强制） |
| 失败锁定 | 连续 5 次失败锁定 15 分钟 |
| 会话 | JWT access 2h + refresh 7d；Redis 存黑名单；空闲 8h 失效 |
| 单点登录 | 同账号允许 3 个活跃会话；超限踢最早 |
| 退出 | 清 token + 加黑名单 |

### 4.2 传输与存储

| 项 | 要求 |
|---|---|
| 传输 | 全站 HTTPS（TLS 1.2+）；内网也启用 |
| 数据库 | 连接加密（可选）；备份文件加密 |
| 敏感字段加密 | 施工人员身份证号（AES-256）；AI api_key（AES-256）；银行账号 |
| 密钥管理 | 环境变量或配置中心；**禁止提交仓库**；定期轮换 |
| 文件 | 存 NAS；DB 只存相对路径；临时 URL 5 分钟 |

### 4.3 应用安全

| 风险 | 防护 |
|---|---|
| SQL 注入 | MyBatis 参数化（`#{}`）；禁用 `${}` 拼接（代码扫描） |
| XSS | 输出转义；富文本白名单过滤（工艺文件正文） |
| CSRF | SameSite Cookie + 关键操作二次校验 token |
| 越权 | 服务端权限 + 数据范围拦截（03 册） |
| 文件上传 | 扩展名白名单 + 真实 MIME 校验 + 重命名 + 杀毒扫描（可选） |
| 路径穿越 | 文件路径白名单 + 规范化校验 |
| 暴力破解 | 登录限流（IP + 账号双维度） |
| 批量导出滥用 | 单次 5 万行上限 + 频率限制（10 次/小时）+ 审计 |
| 接口限流 | 全局 100 QPS/实例；单用户 10 QPS；登录 5 次/分钟 |
| 敏感信息泄露 | 错误页不暴露堆栈；生产关闭 Swagger；日志脱敏 |
| 依赖漏洞 | 每月 `dependency-check` 扫描；高危必须修复 |

### 4.4 审计与合规

| 项 | 要求 |
|---|---|
| 审计日志 | 全部写操作 + 登录 + 导出 + 下载 + 权限变更（03 册 §7） |
| 不可篡改 | 日志表禁止 UPDATE/DELETE（DB 账号权限限制） |
| 保留 | 永久（2 年热 + 归档） |
| 脱敏 | 日志中的敏感字段替换 |
| 个人信息 | 员工身份证/电话加密或脱敏；第三方人员信息按"最小必要"采集 |
| 数据出境 | 无（全部内网/境内） |

## 5. 信创与私有化

| 项 | 要求 | 验证 |
|---|---|---|
| 数据库 | GreatDB（MySQL 8.0 兼容） | 全量 DDL/DML 在 GreatDB 跑通；禁用 MySQL 8.0.30+ 新特性 |
| 操作系统 | 支持国产 Linux（麒麟/统信） | 容器化部署屏蔽差异 |
| JDK | OpenJDK 11（推荐）或 8 | 不用 JDK 17+ 特性 |
| 中间件 | Redis / RabbitMQ 国产替代可选 | 通过适配层隔离（避免直接依赖特定 API） |
| AI | 内网私有化部署 | 无公网调用（静态扫描断言） |
| 浏览器 | Chrome/Edge/Firefox 国产内核浏览器兼容 | 冒烟测试 |
| 部署 | 全离线包（含依赖镜像） | 在无外网环境安装成功 |

**兼容性红线**：
- 不使用 MySQL 8.0 的 `JSON_TABLE`、窗口函数的罕见用法、`CTE` 递归（GreatDB 可能不支持）；
- 不使用 `utf8mb4_0900_ai_ci` 排序规则（用 `utf8mb4_unicode_ci`）；
- 时间类型统一 `DATETIME`（不用 `TIMESTAMP` 避免时区陷阱）。

## 6. 可观测性

| 项 | 要求 |
|---|---|
| 日志 | 结构化 JSON；含 traceId、userId、module；按天滚动保留 30 天 |
| 链路 | 每个请求生成 traceId，贯穿 app → ai-gateway → file-service |
| 指标 | Prometheus 采集：QPS、P95 延迟、错误率、DB 连接数、JVM 堆、队列积压 |
| 看板 | Grafana：接口健康、慢查询、任务执行、AI 调用、T+ 同步 |
| 告警 | 错误率 >1%、P95 >3s、队列积压 >1000、磁盘 >80%、备份失败 → 钉钉/邮件 |
| 健康检查 | `GET /actuator/health` 返回 db/redis/mq/disk/file 状态 |
| 慢查询 | 记录 >1s 的 SQL；每月 review |
