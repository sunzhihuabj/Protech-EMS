# 12 · 模块 I：主数据与数据治理（D13）

> 主数据是全系统 70% 价值的地基——主数据烂了，后面所有看板与成本都是错的。
> 本册的三条铁律：**建档只有一处、下游只能选、编码不可变。**
> 规则编号 `FR-MDM-nn` / `FR-GOV-nn` / `FR-ARC-nn`。

---

## 1. 模块目标

| 目标 | 定义 | 反面（现状） |
|---|---|---|
| 唯一入口 | 六类主数据（客户/风场/项目/物料/供应商/货位）各只有一个写入入口 | 各部门各建一套，142 个签约主体、100 余项目一物多名 |
| 能选不填 | 下游所有引用主数据的字段都用下拉（可搜别名） | 派工单手输项目名，2,051 条台账带编码的仅个位数 |
| 编码不可变 | 编码生成后永不修改、永不复用 | "编码在撒谎" |
| 别名可搜 | 一个项目挂多条历史叫法，怎么叫都搜得到 | 现场叫"鹰头岭"，档案里叫"广西国华鹰斗岭" |
| 治理可重复 | 清洗是每月能跑一次的流水线，不是一次性运动 | 命名规范发布 19 天，执行率 0 |

## 2. 主数据建档

### 2.1 六类主数据与唯一入口

| 主数据 | 编码 | 唯一写入角色 | 建档时点 | 关键约束 |
|---|---|---|---|---|
| 客户主体 | `C{4位}` | R18 建档专员 | 新客户首次合作 | 三级树（集团/区域/项目公司）+ 三级角色（业主/整机厂/签约主体） |
| 风场 | `WF{YYYY}-{NNN}` | R18 | 首次获得风场信息 | 一地一档；同名不同业主分别建档 |
| 项目档案 | `PJ{YYYY}-{NNNN}` | R18（合同评审前） | 合同评审前 | 一风场一档案；多产品挂子项 |
| 物料 | 8 位数字主干 | 工艺部 + R18 | 新品/新料 | 双码检测；单位受控 8 种 |
| 供应商 | `S{4位}` | R09 采购 | 准入时 | 五阶准入；资质有效期 |
| 货位 | `{仓库}-{库区}-{排}-{列}-{层}` | R11 仓储主管 | 库区规划 | 三色标识；二维码标签 |

> 其他部门只能"申请建主数据"，由对应角色受理。这是 BR-MDM-01。

### 2.2 客户主体三级树

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-MDM-01 | 主体建档 | 必填：名称、level、customer_type、group_name；名称查重（同名称拒绝） |
| FR-MDM-02 | 三级树展示 | 集团→区域/省级→项目公司；折叠；按集团统计项目数/合同额 |
| FR-MDM-03 | 集团归并视图 | 展示"集团/主体数/订单行数/占比"（对应 142→14 分析）；一眼看集中度 |
| FR-MDM-04 | 待归类清单 | `group_name='其他/待归类'` 单列一页，可批量指定集团；数量作为质量指标 |
| FR-MDM-05 | 主体别名 | 可挂多条（历史写法/简称/错别字）；搜索命中的是同一主体 |
| FR-MDM-06 | 主体停用 | 有引用时只能停用；停用后下拉不可选但历史单据正常显示 |
| FR-MDM-07 | 内部关联方 | `is_internal=1`（特固兰）按独立法人处理，不计入客户统计 |
| FR-MDM-08 | 主体合并 | 重复主体合并：子停用 + 引用改挂 + 别名迁移；需二次确认 + 审计 |

### 2.3 风场与项目档案

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-MDM-09 | 风场建档 | 名称须为业主规范全称，自动去书名号/多余空格/"项目/工程"尾缀 |
| FR-MDM-10 | 一地一档 | 同 `省+市+县+名称` 拒绝重复；同名不同业主提示"可能撞名，请核对业主" |
| FR-MDM-11 | 期次提示 | `phase_count>1` 时要求选期次或标注"未分期" |
| FR-MDM-12 | **三重查重** | 提交前依次查：① 风场全称精确；② 常用简称 + 全部别名（相似度 ≥0.6）；③ 业主 + 地名。命中任一 → 展示对比卡 → 选"关联已有"或"确认新建（填理由 ≥10 字）" |
| FR-MDM-13 | **名称自动生成** | 输入 4 项（业主规范名/风场全称/期次/订单类型）→ 输出：标准名、口语名、查重结果、编码建议。规则：`标准名 = 业主规范名－地名（去尾缀）－期次`；期次空填"—" |
| FR-MDM-14 | 禁止写法提醒 | 输入含地名但不含业主名 → 红字提示"同一地名可能同时存在三峡/华能/华电的风场，请补业主名" |
| FR-MDM-15 | 关键 12 项校验 | 未填全时"提交"置灰并高亮；其余字段可后续补（显示"待补 N 项"） |
| FR-MDM-16 | 一风场一档案 | 同 `farm_id+phase` 下同产品线已有 ACTIVE 项目 → 拒绝，提示"请在该项目下新增产品子项" |
| FR-MDM-17 | 产品子项 | 项目详情内增删子项（产品线/合同号/台数/质保起止）；子项不单独生成编码 |
| FR-MDM-18 | 合同关联 | 项目与合同多对多；项目详情展示全部关联合同；合同详情展示关联项目 |
| FR-MDM-19 | 状态自动流转 | 按 02 册 7.2；不提供手工改状态（除"关闭"需审批） |
| FR-MDM-20 | 项目变更单 | 仅三类：风场信息补全/主体变更/期次拆分；需审批；**只有 R18 可执行**；变更留痕 |
| FR-MDM-21 | 排产单待关联 | `order_type=OEM_INSTALL` 且无风场 → `farm_pending=1`，列表橙色标记"待关联风场"，**不计入异常** |
| FR-MDM-22 | 未关联风场清单 | 独立报表：合同号/排产批次/机型/台数/签约日/已过天数/催办；可导出；作为商务周度常态管理表 |
| FR-MDM-23 | 别名库 | 全量别名检索；批量登记；只增不删（删除需 R03 + 审计） |
| FR-MDM-24 | 全局搜索 | 输任意编码/别名/客户名 → 返回匹配的项目/合同/物料/工单（分组，各最多 5 条） |

### 2.4 物料主数据

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-MDM-25 | 物料建档 | 编码必须符合 8 位数字主干或已登记字母前缀；新增强制过归一化词典 + 查重 |
| FR-MDM-26 | **双码检测** | 保存时：同名称同规格已有编码 → 阻断"疑似一物多码"；同编码已有不同名称 → 阻断"一码多物" |
| FR-MDM-27 | 编码段冻结 | 字母前缀体系（M/D/TL）只读不可新增；新增一律进 8 位数字段 |
| FR-MDM-28 | 虚拟件 | 采购用中间件必须申请 `V-` 前缀虚拟码；BOM 无编码行发布前必须补码 |
| FR-MDM-29 | 单位受控 | 只能从 8 种选；历史异常单位（只/根/把/标准件/组）导入时映射并记映射表 |
| FR-MDM-30 | 替代关系 | 停用物料必须指定替代料；`md_code_map` 记录旧码→新码 |
| FR-MDM-31 | 安全库存 | 可设上下限；低于下限进"待补货清单"；高于上限提示积压 |
| FR-MDM-32 | ABC 分类 | 按消耗金额自动算 A/B/C；可人工调整 |
| FR-MDM-33 | 受控物料 | 安全件/关键件标 `is_controlled=1`，出库需复核 |

## 3. 编码引擎

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-MDM-40 | 统一取号 | 全部走 `sys_code_sequence`；禁止代码里拼字符串 |

## 4. 数据治理工作台

### 4.1 六个质量指标

| 指标 | 公式 | 目标 | 频率 |
|---|---|---|---|
| 合同档案完整率 | 关键 12 项全非空的合同 ÷ 已签合同 | ≥95% | 月 |
| T+ 合同号挂载率 | 已回填 t_plus 合同号 ÷ 已建档合同 | ≥95% | 月 |
| 项目编码挂载率 | 派工/工单挂 project_id ÷ 总数 | ≥95% | 月 |
| 一物多码月新增 | 当月新增触发同物异码检查的组数 | 0 | 月 |
| BOM 变更正式单率 | 走 ECN 的变更 ÷ 全部变更 | 100% | 月 |
| 非项目行混入率 | 非项目事项行 ÷ 全部填报行 | ≤1% | 月 |

### 4.2 功能需求

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-GOV-01 | 命名规范校验 | 正则 `^{标识段}-{类型码}-{主题}-{YYYYMMDD}-V\d+(\.\d+)?-{责任人}\.ext$`；输出合规率、不合规清单、典型反例（含 `(1)` 副本） |
| FR-GOV-02 | 批量改名 | 生成"原名→新名"预览；逐条勾选；执行前自动备份；支持按批次一键回滚 |
| FR-GOV-03 | 归一化词典 | 三类：错别字（格兰/葛兰→格兰头）、符号（Φ/φ、×/X/*）、单位（MM/mm）；物料查重与建档共用 |
| FR-GOV-04 | 清洗-抽取 | 导入多来源清单（台账/T+ 导出/工单/文件名）；统一字段 raw_name/source_file/source_type/count |
| FR-GOV-05 | 清洗-归一 | ① 去尾缀空格；② 提取地名与业主线索；③ 相似度聚类（≥0.6）；④ 输出候选组 + 归并依据 |
| FR-GOV-06 | 清洗-确认 | **只做选择题**：同组是否同一风场？是/否/待核实；每批 ≤50 组；支持批量 |
| FR-GOV-07 | 清洗-回写 | 生成"旧名→标准名+编码"映射；**只允许回写"项目名称"一列**；原值写别名库；其他字段不动 |
| FR-GOV-08 | 回写校验 | 每批回写后校验命中数；命中数 <预期 90% → 立即停止并报告 |
| FR-GOV-09 | 非项目行剔除 | 识别"公司/内业""证件复审""休假〔非现场〕"等，归入"非项目事项"，不建档案 |
| FR-GOV-10 | 双码检测批跑 | 全库扫描：一物多码（名称+规格归一后相同、编码不同）、一码多物、A 级真冲突（材质/尺寸互斥） |
| FR-GOV-11 | BOM 13 条校验批跑 | 见 06 册 §5.1；结果存 `bom_qc_result`；按产品线出得分 |
| FR-GOV-12 | 治理工单 | 每个待处理项可派单给责任人，带期限；逾期进红灯卡 |
| FR-GOV-13 | 质量看板 | 六指标：目标/实际/状态灯/12 周趋势；低于目标标红 |
| FR-GOV-14 | 治理审计 | 所有治理动作（跑批/改名/回写/回滚）写审计，含批次号 |
| FR-GOV-15 | 只读审计 | 治理跑批不得修改源文件（加密文件走本机办公通道，先备份） |

### 4.3 业务规则

| 编号 | 规则 |
|---|---|
| BR-MDM-01 | 项目档案只在 R18 建一次；其他部门只能"申请"（服务端校验角色） |
| BR-MDM-02 | 下游任何表单的 project_id 必须来自下拉；接口层拒绝接收"手输项目名" |
| BR-MDM-03 | 编码不可修改（数据库触发器 + Service 拦截） |
| BR-MDM-04 | 别名只增不删；删除需 R03 + 审计 |
| BR-MDM-05 | "待关联风场"不视为数据缺陷，报表单列，不做扣分 |
| BR-GOV-01 | 自动回写只动"名称"列，且保留原值到别名库；金额/日期/人员一律不动 |
| BR-GOV-02 | 任何批量操作必须先预览、再执行、可回滚；无预览不得执行 |
| BR-GOV-03 | 一物多码合并：保留用量大的编码，另一个设停用（不删除），写 md_code_map |

## 5. 档案管理

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-ARC-01 | 档号生成 | `{主体码}-{YYYY}-{门类}-{期限}-{4位}`；同年度同门类同期限连续 |
| FR-ARC-02 | 档案登记 | 必填：档号、门类、题名、年度、期限、盒号、位置、形成部门、移交人；可关联合同/项目 |
| FR-ARC-03 | 合同互索引 | 合同建档后一键带出合同要素；`ct_contract.archive_no` 与 `arc_archive.archive_no` 互为索引 |
| FR-ARC-04 | 归档时限提醒 | 合同：签订后 30 日；证照：取得后 15 日；工程：验收后 30 日；文书：次年 3/31；超期进提醒清单 |
| FR-ARC-05 | 借阅申请 | 填借阅人/档号/用途/期望归还日；按门类路由审批（一般=部门负责人；合同财务人事=归口+企管双批；证照外带=分管副总） |
| FR-ARC-06 | 借出归还 | 原件借出 ≤5 工作日；逾期提醒；逾期 15 日上报企管负责人 |
| FR-ARC-07 | 电子查阅 | 在线查看附件（水印含查阅人+时间）；下载受权限控制并留痕 |
| FR-ARC-08 | 期满鉴定 | 每年 12 月自动汇总到期档案，生成鉴定清单 |
| FR-ARC-09 | 销毁清册 | 档号/题名/期限/理由/鉴定意见/会签/批准/监销人；审批链：档案员→形成部门→企管→总经理 |
| FR-ARC-10 | 移交清册 | 年度移交与异动交接；三方签字（移交/接收/监交）留档 |
| FR-ARC-11 | 档案台账 | 实物总目录 + 盒内目录两级；电子台账季度备份 |
| FR-ARC-12 | 温湿度巡检 | 每周记录；超标处置与复测（纸质记录电子化，不做物联网） |

**关键规则**：
- 未编号合同档案室不接收（登记必须带 contract_no）；
- 档号一经登记不可改；门类或期限变更走"重新鉴定"并保留原档号作废记录；
- 销毁必须双人监销，清册永久保存；电子档案销毁需同步销毁全部备份。

## 6. 异常处理

| 场景 | 行为 |
|---|---|
| 查重命中但用户坚持新建 | 记录 `dedup_override_reason`，进"建档复核"清单，商务主管周抽查 |
| 名称生成器无法识别地名 | 保留原文并提示"请手工确认地名片段"，允许编辑生成结果 |
| 一个填报值含两个风场（如"乐嶂·鹰头岭"） | 弹窗要求拆分：生成 2 个待核实建档项，不允许合并成 1 个 |
| 导入时主体名称近似（>0.8） | 归入"待确认归并组"，不自动合并 |
| 项目已有关联单据仍要变更主体 | 允许，但需说明影响并通知财务（合同/开票主体可能同步变更） |
| 治理回写命中数不足 | 立即停止并报告"替换不完整"；不继续后续批次 |
| 物料双码检测误报（规格确实不同） | 允许"确认非重复"并填理由；记入白名单，下次不报 |

## 7. 验收要点

1. 输入"三峡新能源 + 云南姚安大龙口风电场 + 二期 + 业主技改" → 标准名 `三峡新能源－姚安大龙口二期`、口语名 `大龙口二期`、编码建议 `PJ2026-0001`。
2. 用"大龙口二期"作为新项目简称提交 → 三重查重拦截，可"关联已有"。
3. 新建项目只填 8 个字段 → 提交置灰，高亮缺失的 4 个关键项。
4. 同风场同期次已有"自动消防"项目 → 再建被拒，提示"请新增产品子项"。
5. 全局搜索输"鹰头岭" → 命中"国家能源集团－广西鹰斗岭"。
6. 导入 142 条主体 → 显示"14 集团 / 142 主体 / 待归类 39 条"。
7. 新建物料名称规格与已有完全一致 → 阻断并显示已有编码。
8. 50 并发取合同号 → 无重复。
9. 上传含 `《9月份开票明细 (1).xls》` 的清单 → 合规率正确，该文件判"副本式命名"。
10. 输"秀山膏田项目"与"重庆秀山膏田项目" → 聚为同一候选组，依据"地名一致、业主待补"。
11. 回写后别名库新增 2 条；回滚后原名恢复、别名保留。
12. 档号 `PRT-2026-HT-Y-0007` 格式正确且连续。
