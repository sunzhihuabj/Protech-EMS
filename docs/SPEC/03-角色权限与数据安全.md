# 03 · 角色权限与数据安全

> 覆盖 D00 中的权限部分，以及全系统的数据安全约束（脱敏、水印、端限制、AI 隔离）。
> 本册是**安全类验收的唯一依据**：BR-06/07/08 三条硬卡点在此定义。

---

## 一、三维权限模型

```
用户 User
  ├── 属于 → 部门 Department
  ├── 拥有 → 角色列表 Role[]
  │            ├── 菜单权限（Menu）
  │            ├── 操作权限码（Permission Code）
  │            └── 数据范围等级（Data Scope）
  └── 参与 → 项目 Project[]（决定 PROJECT 范围）
```

### 1.1 数据范围五级

| 等级 | 标识 | SQL 自动追加条件 | 典型角色 |
|---|---|---|---|
| 本人 | `SELF` | `created_by = :me OR assignee_id = :me` | 商务专员、技术员、采购员、操作工 |
| 本部门 | `DEPT` | `department_id = :myDept` | 部门主管、质检员、库房、计划 |
| 本部门及下级 | `DEPT_SUB` | `department_id IN (:myDeptTree)` | 中心负责人（技术中心下挂两组） |
| 项目成员 | `PROJECT` | `project_id IN (SELECT project_id FROM prj_member WHERE user_id=:me AND is_active=1)` | 工程技术部、系统集成组 |
| 全局 | `ALL` | 无附加条件（但仍受脱敏约束） | 总经理、板块负责人、财务 |

> **关键规则**：数据范围只控制"能看到哪些行"，**不控制字段是否脱敏**。两者独立判断——财务是 ALL 但可看金额；总经理是 ALL 但不可改单据；仓储是 DEPT 且看不到价格。

### 1.2 权限码规范

格式 `模块:操作[:对象]`，全小写下划线分隔。示例：`contract:view_price`、`project:task:assign`、`file:download`。

**判定顺序**：JWT 取角色 → 查角色权限码集合（Redis 缓存 30 分钟）→ 命中则放行 → 未命中返回 403 + `{missingPerm: "xxx"}`。

**实现**：
- 后端：`@RequirePermission("contract:view_price")` 注解 + AOP 拦截器（在 Controller 方法上）
- 数据范围：MyBatis-Plus `DataScopeInterceptor` 自动改写 WHERE
- 前端：`v-permission="'contract:edit'"` 只控制显隐；**不得作为唯一防线**

## 三、脱敏规则（BR-06）

### 3.1 六类敏感字段

| 表 | 字段 | 脱敏条件 | 返回方式 |
|---|---|---|---|
| ct_contract | amount, payment_terms | 无 `contract:view_price` | `null` → 前端 `***` |
| ct_contract_payment_plan | amount, percentage | 无 `contract:view_price` | `null` |
| ct_invoice / ct_receipt | amount, tax_amount | 无 `contract:view_price` | `null` |
| scm_purchase_order | total_amount | 无 `scm:order:view_price` | `null` |
| scm_purchase_order_item | unit_price, amount | 无 `scm:order:view_price` | `null` |
| md_supplier | supplier_name, contact, phone | 无 `scm:order:view_price`（供应商本人除外） | `供应商A***` |
| cost_item / cost_snapshot | amount, 各成本项 | 无 `cost:view` | `null` |
| md_material | cost_price | 无 `cost:view` 且非 R09/R15 | `null` |
| inv_transaction | cost_price, amount | 无 `cost:view` | `null` |

### 3.2 实现机制（三层）

```
① MyBatis 拦截器：查询结果集 → 按当前用户权限码 → 命中脱敏字段置 null
② 序列化层：@Sensitive(perm="contract:view_price") 注解 + Jackson Serializer 兜底
③ 日志层：写 sys_operation_log 前对 request/response 做敏感字段替换
```

**硬要求**：
- 脱敏在**服务端**完成，前端 `v-permission` 只负责把 `null` 显示成 `***`。
- 直接构造 HTTP 请求绕过前端，仍返回 `null`（验收用例 UC-SYS-05 验证）。
- 导出（Excel/PDF）同样脱敏，且导出行为写审计。

### 3.3 明文可见的例外（必须留痕）

| 场景 | 谁 | 条件 | 留痕 |
|---|---|---|---|
| 财务对账 | R15 | 无（ALL + view_price） | 每次导出写审计 |
| 合同评审 | 评审人 | 仅评审期间可见金额 | 评审记录 |
| 紧急排障 | R03 | 需 R02 临时授权，最长 4 小时 | 授权单 + 审计 |

## 四、文件安全与水印（BR-07）

### 4.1 四种水印形态

| # | 形态 | 内容 | 技术实现 | 刷新 |
|---|---|---|---|---|
| **W1** 页面水印 | `{姓名} - {部门} - {YYYY-MM-DD HH:mm}` | 前端 Canvas 生成平铺背景，`pointer-events:none`，倾斜 25°，`rgba(0,0,0,0.1)`，14px | **每 10 秒刷新时间 + 随机微偏移**（防截图定位去水印） |
| **W2** 下载水印 | `{公司全称} \| {部门} \| {姓名} \| {电话}` | 后端 PDFBox 在每页对角/网格平铺半透明文字 | 一次性生成，与下载人绑定 |
| **W3** 照片水印 | `{公司简称} \| {部门} \| {姓名} \| {电话} \| {拍摄时间}` | 服务端 Graphics2D 合成，右下角 + 对角 | 合成后**不保留原图** |
| **W4** 小程序水印 | 同 W2 + 项目名 | PDF.js/Canvas 叠加，禁打印 API | 打开时实时渲染 |

### 4.2 下载控制链（BR-07）

```
用户点下载
  → 校验 file:download 权限 + 项目成员身份
  → 判断文件类型：
      ├─ Office（docx/xlsx/pptx）→ OnlyOffice/LibreOffice 转 PDF → 加 W2 水印
      ├─ PDF → 直接加 W2 水印
      ├─ 图片 → 加 W3 水印后返回
      └─ CAD/压缩包 → 打包并在包内附水印说明文本（不返回原始单文件）
  → 返回带水印文件，临时签名 URL（5 分钟有效）
  → 写审计（人/文件/时间/IP）
```

**硬要求**：
- **任何路径都不返回原始文件**；`file:view_original` 权限默认不存在于任何角色。
- 打印：PC 端页面水印随打印输出；小程序禁用 `wx.printPage` 相关能力。
- 临时 URL 直接暴露文件服务器路径视为缺陷（验收用例 UC-SYS-11）。

### 4.3 文件状态与可见性

| 状态 | 可见范围 |
|---|---|
| DRAFT 草稿 | 仅创建者 + 文件夹编辑权限者 |
| PUBLISHED 已发布 | 项目内全部授权成员（含下游部门） |
| PAUSED 暂停 | 上游可见，**下游不可见、不可搜**；需填暂停原因 |
| ARCHIVED 归档 | 只读；随档案移交 |

**暂停/恢复**：上游（如技术部）可对已发布文件执行暂停；重新发布后通知此前受影响用户。

### 4.4 上传限制

单文件 ≤500MB；扩展名白名单（doc/docx/xls/xlsx/ppt/pptx/pdf/jpg/jpeg/png/dwg/dxf/zip/rar）；禁止 exe/bat/sh/js/vbs；文件重命名为 UUID 存储；计算 sha256 去重与完整性校验；Office 文件上传后异步转 PDF 预览。

## 五、第三方隔离（BR-08）

### 5.1 端限制

| 角色 | PC Web | 微信小程序 | H5 |
|---|---|---|---|
| R17 第三方-施工人员 | **403 拒绝** | 允许 | 允许（但功能受限） |
| R16 第三方-商务/财务 | 允许（仅门户页） | 允许 | — |
| 内部员工 | 允许 | 允许 | 允许 |

**实现**：登录时校验 `user_type` + `User-Agent`/来源端标识；R17 在 PC 登录直接返回 403 并提示"请使用微信小程序登录"。

### 5.2 数据隔离

| 隔离维度 | 规则 |
|---|---|
| 项目级 | R17 只能访问 `thd_worker_project` 中授权且未过期的项目；未授权项目连文件名都搜不到 |
| 供应商级 | R16 只能看 `supplier_id` 等于自己企业的采购订单；不同供应商订单互不可见 |
| 价格隔离 | R16 的订单接口不含 `unit_price`/`total_amount`（不是脱敏，是**根本不查这些字段**） |
| 文件隔离 | R17 只能看已发布文档，不能看草稿；不能看会议纪要、内部往来 |
| 账号生命周期 | 项目结束 → `thd_worker_project.status=FROZEN`；账号保留但无项目可访问；下次合作解冻（校验资质有效期） |

### 5.3 施工人员准入与冻结

```
班组准入：注册 → 资质审核 → 现场考察 → 培训考核 → 合格名录（五阶）
人员入场：身份证 + 资质证书 + 保险 + 安全培训记录 在线提交 → 工程部审核 → 行政开通账号（PENDING）
项目授权：工程部加入项目成员 + 分配可见文件范围 → 账号 ACTIVE
离场冻结：工程部移出项目 → FROZEN（数据保留）
重新入场：检查资质/保险是否过期 → 解冻
```

**硬要求**：保险过期或安全培训过期的人员，授权时直接拒绝并提示原因。

## 六、AI 隔离

| 约束 | 实现 |
|---|---|
| 唯一出口 | 业务代码只能调 `AiGatewayService`，不得直接 HTTP 调模型 |

## 6A · 主题配置与个性化（12 套预设，V3.1 新增）

### 6A.1 需求

系统提供 **12 套预设主题**，Web 端可切换；清单、色值与切换效果图见 `visual/主题色候选-切换对比.html`（持续维护的单一事实源）。

| 层级 | 谁定 | 存哪 | 规则 |
|---|---|---|---|
| 系统默认主题 | R03 系统管理员 | `sys_config` key=`app.theme.default` | 新用户与未做个人选择的用户生效 |
| 用户个人主题 | 每个用户（个人设置 → 外观） | `sys_user.theme_code` | 覆盖系统默认；空值=跟随默认 |
| 模式叠加 | 每个用户 | 同上 `mode_code` | 投屏亮/投屏暗为**独立维度**，与主色主题正交 |

### 6A.2 权限码

| 权限码 | 说明 |
|---|---|
| `system:theme:manage` | 设定系统默认主题、启停某套主题（仅 R03） |
| `profile:theme:switch` | 切换个人主题（**全员默认拥有**，不需要授权） |

### 6A.3 技术机制（Element UI 2.15 的现实约束，不得偏离）

- **采用"预编译主题包"方案**：12 套 `element-variables.scss` 在构建期各编译出一份完整 CSS（Element + 项目 override 打在一起），运行时按 `theme_code` 动态加载对应样式表（`<link>` 切换或注入 `<style>`），**切换零编译、零接口调用**。
- **禁止**运行时用 CSS 变量全量替换 Element 颜色的 hack 方案（工程复杂、与"编译 theme-chalk 源码"路线冲突、语义色易失控）。
- 默认主题随主包加载；其余 11 套按需懒加载，单包体积控制（见 15 册性能口径）。
- **语义色语法在 12 套主题下全部不变**：Metric（暗红绿+▲▼）与 Status（亮色+形状）两套语法是全局约束，任何主题不得重定义。
- **不做"用户自定义色值"**，只允许从 12 套预设中选择——避免对比度失控与合规风险。
- 切换即时生效（无刷新或局部刷新均可），偏好持久化到服务端，多端（PC/小程序）一致；小程序端不提供主题切换（只跟随默认），降低包体积。

### 6A.4 准入门槛（12 套全部必须达标，否则不得上架）

每套主题必须通过 9 项主题体检（见 visual 稿），其中硬性三条：
1. 主色文字白底对比 ≥4.5:1；
2. 「进行中」标签（主色浅底）与「合格」标签（绿底）在 100% 缩放下可区分；
3. 主色与 info 语义色色相间距 ≥15°，否则该主题必须同时声明"info 改灰"并写入该主题包的说明。

不达标的候选**不得作为预设上架**（如墨绿 H145 已实测与合格标签混淆，属不成立）。
