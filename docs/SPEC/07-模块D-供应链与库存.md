# 07 · 模块 D：供应链与库存（D04 + D05）

> 解决断点③采购、④库房出入库。本模块有一条**不可动摇的架构原则**（见 00 册 C-04）：
> **T+ 是库存数量的唯一权威；本系统只维护"事务流水 + 缓存 + 对账"。**
> 规则编号 `FR-SCM-nn` / `FR-INV-nn`。

---

## 1. 库存架构（先讲清这一条，否则会做错）

### 1.1 三方职责

| 角色 | 存什么 | 谁写 | 用途 |
|---|---|---|---|
| **T+** | 存货账面数量、成本、凭证 | 只有 T+ 写（通过其自身单据或接口） | 财务唯一账 |
| **本系统** | 库存**事务流水**（`inv_transaction`，只增不改） | 业务动作触发（扫码/到货/发货/盘点） | 业务事实、追溯、成本归集 |
| **缓存** | 现存量/可用量的**只读副本**（`inv_stock_cache`，TTL 5 分钟） | 定时或按需从 T+ 拉取 | 页面查询性能、齐套计算 |

### 1.2 出入库完整链路

```
【入库】
采购到货 → 质检合格 → 仓储扫物料码 → 选库位 → 填数量/批次 → 提交
  → 本地写 inv_transaction(RECEIPT, sync_status=PENDING_SYNC, idempotency_key)
  → 调 T+ 其他入库单接口
      ├─ 成功 → 回写 t_plus_voucher_no, sync_status=SYNCED；刷新 inv_stock_cache
      └─ 失败 → 重试 3 次（5s/30s/120s）→ 仍失败置 EXCEPTION → 进"待人工处理"
  → 每日 23:00 对账：Σ本地事务 vs T+ 流水 → 差异入 int_reconcile_diff / inv_reconcile

【出库】
发货单/派工/补货/领料 → 生成出库申请 → 仓储扫码出库
  → 同上链路（txn_type=ISSUE）
  → 出库前校验 inv_stock_cache.qty_available ≥ 出库量（缓存过期则强制刷新）
```

### 1.3 三条硬规则

| 编号 | 规则 | 为什么 |
|---|---|---|
| BR-INV-01 | 本系统**不建权威库存数量表**；不得用本地数量覆盖 T+ | 否则必然出现两套账 |
| BR-INV-02 | 出库前必须校验可用量；不允许负库存（特批需 R02 审批 + 留痕） | 账实相符的前提 |
| BR-INV-03 | 每条事务必须有 `idempotency_key`（`来源单号+行号+动作`），重复提交返回首次结果 | 扫码手抖、网络重试常见 |

## 2. 供应链（SCM）

### 2.1 供应商五阶准入 + 五档分级

**五阶准入状态机**：

```
REGISTERED（注册）
  → QUALIFIED（资质审核通过）
  → VISITED（现场考察通过）
  → SAMPLED（样品认证通过）
  → APPROVED（合格名录）
任一步 → REJECTED（不通过，可重新申请）
```

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-SCM-01 | 供应商注册 | 公司名、统一社会信用代码、联系人、电话、地址、经营范围；编码 `S{4位}` |
| FR-SCM-02 | 五阶流转 | 每阶需上传对应材料 + 审核人签署；阶段可"通过/不通过"；不通过需理由 |
| FR-SCM-03 | 资质文件管理 | 营业执照、质量体系证书、行业资质、银行信息；记录发证/有效期 |
| FR-SCM-04 | 资质到期提醒 | 到期前 30 天提醒采购；到期未更新 → 状态自动 `SUSPENDED`，不能创建新订单 |
| FR-SCM-05 | 五档分级 | 战略/优选/合格/限制/淘汰；由综合评分 + 人工调整（需理由） |
| FR-SCM-06 | 分级联动 | 战略供应商优先推荐、优先议价；限制级下单需额外审批；淘汰级不可选 |
| FR-SCM-07 | 供应商评价 | 每季度自动生成评价任务；四维：来料合格率、交期达成率、服务响应、价格竞争力 |
| FR-SCM-08 | 评分权重 | 默认 质量 40% / 交期 30% / 服务 20% / 价格 10%（可配） |
| FR-SCM-09 | 评价结果 | 生成排名表；影响后续供应商推荐顺序；低于阈值进"观察名单" |
| FR-SCM-10 | 黑名单 | 重大质量/安全事故或连续低分 → 列入黑名单（需 R02 审批）；禁止参与新项目；有解除日期 |

### 2.2 采购

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-SCM-11 | 采购需求四来源 | ① BOM 齐套缺料（自动）；② 安全库存触发；③ 项目专用（手工，需挂项目）；④ 备货（需总经理审批） |
| FR-SCM-12 | 需求单 | 必填：来源、项目（①③必填）、物料、数量、期望到货日；编号 `PR-{YYYYMM}-{4位}` |
| FR-SCM-13 | 需求合并 | 同供应商的多个需求可合并为一张 PO；不同项目分行保留（成本归集维度） |
| FR-SCM-14 | 供应商推荐（AI-005） | 按物料历史采购 + 评分推荐候选；显示评分、参考价、交期 |
| FR-SCM-15 | 采购订单 | 编号 `PO-{YYYYMM}-{4位}`；多项目分摊需填分摊数量；总金额自动算 |
| FR-SCM-16 | 价格脱敏 | 无 `scm:order:view_price` 的角色，`unit_price`/`total_amount` 返回 null（BR-06） |
| FR-SCM-17 | 下发 | 下发后通知库房/质检/生产（通知内容不含价格）；供应商门户可见（无价格） |
| FR-SCM-18 | 分批到货 | 支持部分到货；`received_qty` 累加；全部到货才可关闭 |
| FR-SCM-19 | 超收控制 | 超收 ≤5% 允许；>5% 需审批 |
| FR-SCM-20 | 物流跟踪 | 录入运单号与承运商；接快递100 后自动拉轨迹（一期手工录入 + 时间线展示） |
| FR-SCM-21 | 采购退货 | 质检不合格 → 发起退货（数量/原因）；退货单关联原 PO；状态→部分/全部退货；通过 T+ 冲减 |
| FR-SCM-22 | 价格库 | 记录每次采购单价（物料+供应商+日期）；支持趋势分析、同比、异常价预警 |

## 4. 业务规则汇总

| 编号 | 规则 |
|---|---|
| BR-SCM-01 | 未准入（非 APPROVED）的供应商不得下单 |
| BR-SCM-02 | 采购订单下发后不可改供应商与单价；只能作废重开 |
| BR-SCM-03 | 采购价格对仓储、生产、工程角色不可见（BR-06） |
| BR-SCM-04 | 备货类采购必须总经理审批；超订单需求 20% 的备料必须走评审并明确消化路径 |
| BR-INV-01~03 | 见 §1.3 |
| BR-INV-04 | 没有单据不发货：所有出库必须挂 ship_order/dispatch/replenish/领料单 |
| BR-INV-05 | 盘点单进入"已调账"后不可修改；更正走新的调整事务 |
| BR-INV-06 | 差异金额与审批权限由服务端判定，前端不可指定审批层级 |
| BR-INV-07 | 安全件清单由 `sys_config` 维护；清单内物料出库强制走先发后签 |

## 5. 异常处理

| 场景 | 行为 |
|---|---|
| T+ 接口超时 | 重试 3 次（5s/30s/120s）→ EXCEPTION → 接口监控页可批量重试 |
| T+ 返回"库存不足"但本地缓存显示有 | 以 T+ 为准，刷新缓存，提示"账面不足，请核对" |
| 同一到货单重复提交 3 次 | 仅 1 笔事务（幂等键） |
| 扫码物料已停用 | 拒绝入库，提示替代码，可转"临时码申请" |
| 盘点发现账面为负（历史遗留） | 允许生成差异并归因"历史遗留"，走调账 |
| 两司物料串料 | 按 legal_entity 强隔离；跨主体需双人确认 |
| 供应商资质过期仍要下单 | 拒绝；紧急走 R02 审批并记录 |
| 补货安全件 25h 未补签 | 该用户新申请被拒，推送链主，进红灯 |
| 离线队列同步时库存已不足 | 标记冲突，转人工处理，不自动出库 |

## 6. 验收要点

1. 入库扫码提交 → 事务 sync_status=PENDING_SYNC → 同步成功后 SYNCED 并回写 T+ 单号。
2. 同一请求提交 3 次 → 仅 1 笔事务，库存只加 1 次。
3. T+ 接口挂掉 → 事务转 EXCEPTION，业务不中断；恢复后批量重试成功。
4. 断网扫码 5 条 → 联网同步 5 条，无重复。
5. 盘点差异 3,800 元 → 路由到"计划负责人"；越级提交被拒。
6. 未选归因 → 拒绝调账。
7. 同一根因当月第 3 次 → 自动生成专项整改项。
8. 安全件补货 4h 内出库，25h 未补签 → 该用户新申请被拒 + 链主收到消息。
9. 供应商资质过期 → 状态 SUSPENDED，下单被拒。
10. R11 查采购订单 → 单价与总价为 null。
11. 每日对账报告能定位到"某物料某货位差 12 件"。

**声明：本方案为产品设计参考，具体实施请结合公司合规与法务要求确认。**
