# 04 · 模块 A：营销与合同（D01）

> 解决断点①报价→合同。合并 A 的 CRM 与合同管理、B 的合同建档九节点两卡点。
> 规则编号 `FR-CRM-nn` / `FR-CT-nn`。

---

## 1. 模块目标

| 目标 | 定义 | 反面 |
|---|---|---|
| 报价有依据 | 报价值参考历史成交价、同风场人天、成本测算 | 靠个人经验拍价 |
| 合同有编号有要素 | 26 要素 + 唯一编号 + 卡点强制 | 合同台账靠文件夹命名 |
| 交底有回执 | 五类接收人自动分发，需点"已阅" | 合同签了没人看 |
| 回款有节奏 | 收款计划自动生成，7/3/1 天分级提醒 | 回款靠催 |
| 风险有提示 | AI 给红黄绿标签 + 人工复核 | 签完才发现质保金 3% |

## 3. 合同全生命周期

### 3.1 九个节点与两个卡点（B 的核心模型，照此实现）

| 节点 | 动作 | 责任人 | 输入 → 输出 | 时限/系统动作 |
|---|---|---|---|---|
| ① 询价报价 | 报价登记 | R04 | 客户需求 → 报价记录 | 关联商机；带出价格基准 |
| ② 合同起草 | 套范本 | R04 | 范本 → 草案 | 核对六要素：甲乙方/标的/金额/期限/质保/付款 |
| ③ **合同评审 ★卡点一** | 多部门会签 | R05+财务+工程+生产 | 草案 → 评审通过版 | **BR-01：必须带 project_id**；无则先建档；排产单可选"待关联" |
| ④ 签署用印 | 编号+用印 | R04 | 评审版 → 已签合同 | 生成合同号；登记正本份数 |
| ⑤ **建档备案 ★卡点二** | 录 26 要素 | R04 | 已签 → 档案入库 | 用印后 **3 个工作日**；超期冻结开票（BR-02） |
| ⑥ 履约执行 | 下单/备货/派工/发货 | 计划/仓储/工程 | 订单 → 交付 | 全部引用 project_code |
| ⑦ 变更管理 | 补充协议 | R04+R18 | 变更需求 → `-BCn` | 同步更新合同与项目档案 |
| ⑧ 开票与回款 | 开票/收款 | R15 | 验收/节点 → 发票、回款 | 都带合同号 |
| ⑨ 验收·质保·关闭 | 归档 | 商务+工程+档案 | 验收资料 → 归档 | 关闭后 30 日内移交正本、生成档号 |

> **两个卡点承担全部强制力**：③ 不带项目编码不通过——建档动力来自"不建档走不了流程"；⑤ 用印后 3 日不建档，T+ 合同号无法回填、财务无法开票——用结算倒逼建档。其余环节只做"选而不填"。

### 3.3 功能需求：起草与 AI

| 编号 | 需求 | 规则 |
|---|---|---|
| FR-CT-01 | 合同起草 | 必填：名称、性质、我方主体、对方主体、业务类型、金额、税率、付款条件、签订日期；支持从商机/中标价带出 |
| FR-CT-02 | 性质码必选 | XS/CG/KJ；选后业务类型下拉联动过滤 |
| FR-CT-03 | 关联项目 | 可多选；**评审提交前至少 1 个**（BR-01）；排产单可"待关联风场"占位 |
| FR-CT-04 | 付款条件建模 | 支持多条分期：阶段名（预付款/到货款/验收款/质保金）、比例、金额（自动算）、计划收款日 |
| FR-CT-05 | AI 风险分析（AI-001） | 上传未签章文本（Word/PDF）→ 调网关 → 返回风险点（类型/等级/描述/建议）；红黄绿标签；可采纳/忽略 + 补充备注 |
| FR-CT-06 | 风险分析不阻断 | 分析结果随合同保存，**不影响归档**（AI 是辅助不是门禁） |
| FR-CT-07 | AI 信息提取（AI-002） | 上传签章 PDF → 自动提取 12 字段：项目名/合同编号/对方全称/金额/交货地址/联系人/电话/技术附件/交货期/质保期/验收条款/付款条件 |
| FR-CT-08 | 提取确认界面 | 左右分栏；左 PDF.js 预览并高亮提取位置；右可编辑表单；逐字段可改；显示置信度低的字段（黄色标记） |
| FR-CT-09 | 确认归档 | 点"确认无误"→ 保存为正式记录 → 状态→已归档 → 合同主记录锁定（后续修改必须走变更） |
| FR-CT-10 | 提取失败降级 | AI 不可用/超时 → 显示"AI 提取不可用，请手工填写"→ 表单可手工录入，不阻塞归档 |
| FR-CT-11 | 人工修正留痕 | 每个被改过的字段记 `ai_value → human_value`，写入 `ai_feedback`（模型迭代训练数据） |

### 3.7 业务规则汇总

| 编号 | 规则 |
|---|---|
| BR-CT-01 | 合同号一经生成不可改；编号错误只能作废重开（需 R05 审批 + 保留原号） |
| BR-CT-02 | 销售（XS）与采购外包（CG）必须能凭编号直接区分，禁止共用业务码 |
| BR-CT-03 | 存量合同编号不改，登记 `legacy_no` 与 `md_code_map` |
| BR-CT-04 | 用印人 ≠ 建档人时，建档责任仍归经办人（按 handler_id 派任务） |
| BR-CT-05 | 合同 CLOSED 后不可变更；如需重启，新建合同并关联原合同 |
| BR-CT-06 | 一份合同跨多项目时，项目金额按比例拆分，合计须等于合同金额（误差 ≤1 元） |
| BR-CT-07 | 开票累计金额不得超过合同金额（除有增额补充协议） |
| BR-CT-08 | 收款核销以发票为准；无发票回款单列"预收款"，不冲抵应收 |

### 3.8 异常处理

| 场景 | 行为 |
|---|---|
| 评审时项目编码为空 | 阻断 + BR-01 + "去建档"按钮 |
| 建档时对方主体不存在 | 允许"临时新建主体"（自动进待归类），不得跳过 |
| 金额与评审版差 >5% | 提示差异，需原因并重走评审 |
| 补充协议跳号 | 不允许删除已生成协议；只能作废并标"作废" |
| 一份合同跨 3 风场 | 允许；拆分比例合计校验 |
| 逾期未建档但急需开票 | 紧急放行：R02 审批 + 理由 + 进报表 |
| AI 提取字段明显错误 | 人工改；记录到 ai_feedback；不改模型权重（离线训练） |

### 3.9 验收要点

1. 起草不选项目 → 提交评审被拒（422 + BR-01），可跳转建档。
2. 用印生成 `TLD-2026-CG-AZFWXF-0091`，连续不跳号。
3. 用印第 4 个工作日仍未建档 → 进冻结清单，开票返回 422。
4. 上传合同 → AI 风险返回 3 条（1 高 1 中 1 低）；采纳 1 条后记录 is_adopted。
5. 上传签章 PDF → 提取 12 字段填入右侧表单；改 2 个字段后确认 → `ai_feedback` 有 2 条记录。
6. 交底分发 5 人；24h 未阅者收到二次提醒。
7. 收款录入 → 财务确认 → 合同累计回款正确。
