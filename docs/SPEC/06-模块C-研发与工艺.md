# 06 · 模块 C：研发与工艺（D03）

> 解决断点③生产→采购的数据源头问题。本模块的两个核心：**BOM 二维矩阵**（三形态 × 三视图）与 **工艺落线**（工艺文件必须随 BOM 强制产出）。  
> 规则编号 `FR-PLM-nn` / `FR-PCS-nn`。



---

## 1. 模块目标

| 目标        | 定义                                       | 反面（现状）                                        |
| --------- | ---------------------------------------- | --------------------------------------------- |
| BOM 有唯一来源 | A/B/C 三形态各有明确建法；项目 BOM 只能由 Golden BOM 派生 | 每个项目从上一个项目复制改（审计发现免爬器 112 份项目 BOM 高度相似但有编码差异） |
| 视图能转换     | EBOM→MBOM→SBOM 有明确转换规则，变更同步              | "图纸改了、工艺没改"                                   |
| 编码不分裂     | 物料只能从主数据选，禁止空编码与填序号                      | 4,753 行编码列填序号、4,352 行中间件无编码                   |
| 工艺必须落线    | 工艺文件是 BOM 发布的强制配套，不是可选产出                 | 导轨工艺零覆盖（0%）、自动消防 4.7%                         |
| 变更受控      | ECN 必须附旧料处置，影响清单强制生成                     | 331 次变更仅 13 张正式单（3.9%）                        |

## 2. BOM 二维矩阵（本模块的核心设计）

### 2.1 为什么是两个维度

| 维度         | 回答什么                       | 取值                  |
| ---------- | -------------------------- | ------------------- |
| **形态**（横向） | 这个产品要不要建完整 BOM？建到什么程度？     | A 标准 / B 参数化 / C 工程 |
| **视图**（纵向） | 同一份 BOM 在设计/制造/服务阶段分别长什么样？ | EBOM / MBOM / SBOM  |

**只用一个维度会犯两个错**：

- 只用"视图"（A 的原方案）→ 给系统集成项目也建 MBOM，但集成项目没有制造过程，MBOM 是空的，界面留白让人以为漏了；
- 只用"形态"（B 的原方案）→ 给升降机也只建一份清单，但升降机的设计 BOM、制造 BOM、服务 BOM 内容差别很大（服务 BOM 只留可更换件）。

### 2.2 九宫格与建法

| 形态 ↓ / 视图 →                                                         | EBOM 设计                                                    | MBOM 制造                                    | SBOM 服务                       |
| ------------------------------------------------------------------- | ---------------------------------------------------------- | ------------------------------------------ | ----------------------------- |
| **A 标准产品**（升降机 TLDL-300/350、TLDW-300；免爬器 120kg 系列；自动盖板 TLD-20GB-00） | 完整两级：整机 → 部件总成（驱动/导向/电气/安全钳）→ 零件+标准件                       | 由 EBOM 转换：加工艺辅料（端子/扎带/标签）、按装配工序重排、设物料来源    | 由 EBOM 裁剪：只留可更换件与安全件，标注建议更换周期 |
| **B 参数化产品**（爬梯按节数/高度；导轨按塔筒段长）                                       | **模板**：标准节 × 数量公式 + 定制段 + 通用附件包；维护"标准节 BOM + 附件包 BOM"两个小模板 | 同左，加装配工序                                   | 按项目实例生成备件清单                   |
| **C 系统工程**（视频监控/智慧安防、自动消防/安消一体化、技改加装）                               | 工程物料清单：按点位（机舱/塔底/塔筒/升压站）× 设备+线缆+辅材，与设计图纸点位表对应              | **不建**（`mbom_not_applicable=1`，界面明确标"不适用"） | **= 设备档案**：一机一档，售后维修依据        |

### 2.3 三个直接好处

1. **C 类不建 MBOM 但必须显式标注"不适用"**，不是留空——避免被误认为数据缺失。
2. **SBOM 与设备档案合并为一个实体**（`eng_unit.sbom_header_id`），不再各建一套。
3. **B 类的 EBOM/MBOM 都是模板**，只有项目实例才展开——避免"每个订单手工建 BOM"。

### 2.4 转换规则（必须写进 Service）

| 转换          | 规则                                                                                                            | 系统动作                                                     |
| ----------- | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| EBOM → MBOM | ① 复制全部行；② 添加工艺辅料行（`is_process_aux=1`）；③ 按工序重排 `line_no`；④ 设置 `source_type`（自制/外购/外协/标准件）；⑤ 不允许改物料本体（只能改序与加辅料） | 生成新 BOM 头（`bom_view=MBOM`, `source_bom_id=EBOM`），差异可一键比对 |
| EBOM → SBOM | ① 复制全部行；② 过滤：只保留 `is_serviceable=1` 的物料（可更换件/安全件/易损件）；③ 追加建议更换周期                                              | 生成新 BOM 头（`bom_view=SBOM`）                               |
| SBOM → 设备档案 | 项目完工后，按机组实例化 SBOM 行 → 写入 `eng_unit` 与序列号                                                                      | 生成一机一档                                                   |

### 5.1 BOM 数据质量 13 条校验

| #  | 规则            | 级别        | 判定                                    |
| -- | ------------- | --------- | ------------------------------------- |
| 1  | 物料编码为空        | ERROR     | `material_id IS NULL`                 |
| 2  | 编码列被填序号       | ERROR     | 编码匹配 `^\d{1,3}$` 且长度<5                |
| 3  | 物料名称与主数据不一致   | WARN      | 行内快照 ≠ 主数据名称                          |
| 4  | 规格型号为空        | WARN      | 主数据 `spec` 为空                         |
| 5  | 计量单位为空        | ERROR     | `unit IS NULL`                        |
| 6  | 单位被填成类别       | ERROR     | `unit IN ('标准件','钣金件','组','套件')`      |
| 7  | 数量为 0 或负      | ERROR     | `qty_per_unit <= 0`                   |
| 8  | 一物多码          | WARN      | 同名称+同规格归一后有多个 material_id             |
| 9  | 一码多物          | **ERROR** | 同 material_id 在不同 BOM 中名称相似度低于阈值      |
| 10 | 一码多规格（A 级真冲突） | **ERROR** | 同码规格出现互斥材质（不锈钢↔碳钢/镀锌/达克罗）或互斥尺寸（M6↔M8） |
| 11 | 同码多单位         | ERROR     | 同 material_id 出现不同 unit               |
| 12 | 层级序号不规范       | WARN      | 不匹配 `^\d+(-\d+){0,2}$`                |
| 13 | 工艺文件未关联       | INFO      | `process_doc_id` 空且该产品线有工艺文件          |

**执行时机**：① 保存时实时校验 1—7、12；② 发布前全量校验，存在 ERROR 不可发布；③ 每月 1 日全库跑批（13 条），结果存 `bom_qc_result`，得分进治理看板。

## 8. 业务规则

| 编号        | 规则                                          |
| --------- | ------------------------------------------- |
| BR-PLM-01 | 同一对象（形态+视图+型号/项目）只能有 1 份现行 BOM              |
| BR-PLM-02 | 项目 BOM 不得直接修改标准行；只能删行、改量（记录原因）、加项目专用行       |

| BR-PCS-01 | 工艺文件未编号不得发布                                 |
| BR-PCS-02 | 正式工艺文件发布前必须有对应 BOM 已发布（不能"有工艺无 BOM"）        |
| BR-PCS-03 | 工艺文件与 BOM 双向引用字段缺失时，发布检查给出 WARN（不阻断，但计入覆盖度） |

## 9. 异常处理

| 场景                   | 行为                           |
| -------------------- | ---------------------------- |
| 批量粘贴含停用物料            | 标红并提示替代码；可选择"替换为替代料"后导入      |
| 参数化展开参数越界（如塔高超产品范围）  | 提示"超出模板适用范围，需技术确认"，允许强制展开并记录 |
| EBOM→MBOM 转换时已有 MBOM | 提示"已存在现行 MBOM，将生成新版本"，需确认    |
| 一码多规格 A 级冲突在发布时被发现   | 阻断发布，列出冲突组与影响行数，跳转治理工作台      |
| ECN 影响清单为空           | 允许（可能是纯纠错），但需勾选"确认无影响"       |
| 工艺文件暂停后生产已开工         | 提示"该文件已暂停，但存在进行中工单"，通知生产主管   |
| OnlyOffice 服务不可用     | 降级为"上传下载"模式，在线编辑按钮置灰并提示      |

## 10. 验收要点

1. 新建 A 类 EBOM 未选 Golden BOM → 拒绝；选定后派生，差异视图显示 0 处。
2. BOM 行编码填 "1" → 保存报错"编码列疑似填写序号"。
3. 新建 C 类 BOM → MBOM 页签显示"不适用（工程物料无制造过程）"，不是空表。
4. EBOM→MBOM 转换 → 自动加端子/扎带行，按工序重排，差异可对比。
5. 输入塔高 120m、节数 60 → 参数化展开生成 60 节 + 附件包行。
6. 提交 ECN 不填旧料处置 → 拒绝（BR-09）；填后影响清单列出库存/在制/在途数量。
7. 跑 13 条校验 → 覆盖度矩阵显示"导轨 0%（零覆盖）、自动消防 4.7%（严重不足）"，与审计口径一致。
8. 工艺文件未编号 → 发布被拒。
