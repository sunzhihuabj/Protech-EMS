## 一、为什么重构：三个必须解决的问题

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| R1 | **23 册按"编写顺序"组织，不按"开发顺序"组织** | AI Agent 需按 16 册 §六逐片跳读 5—8 册；同一规则分散在 01/04/16/17 四处 | 上下文加载成本高，跨册引用易漏（V3.2→V3.3 已发生 6 次"声称已登记、目标册未改"） |
| R2 | **模块命名双轨**：A—J 字母（04—12 册、21 册）与 D00—D19 域（01 册）并行 | 同一个"库存"既是模块 D（07 册）又是域 D05 | Agent 无法建立唯一模块索引 |
| R3 | **审核发现的 31 条问题**中 3 条 P0（公网暴露面、工期口径、业务前置）、2 条覆盖缺口（报价单、商机来源）未在结构上根治 | 见 §四对照表 | 直接开发会在架构与范围上返工 |

**重构目标**：让一个 AI Agent **只读 1 卷**即可完整实现 1 个模块，只读 2 卷（本篇 00 + 目标模块卷）即可开工；全部规则可定位到"模块—功能—规则"三级编号。
