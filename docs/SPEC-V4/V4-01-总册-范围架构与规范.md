## 一、背景与目标

### 1.1 问题树（材料实证）

```
三套系统各自为政（T+ 财务 / 钉钉 审批 / 售后宝 工程）
  ├─ 六断点：①报价→合同 ②合同→生产 ③生产→采购 ④库房出入库 ⑤发货→安装 ⑥安装→验收回款
  └─ 三大痛点（部门访谈原话）：订单无系统承载、库房账实不符、BOM 边界不清
        ↓ 四类根因
  R1 无唯一主数据入口 → 一物多码/一码多物（BOM 审计 8,764 处缺陷）
  R2 无强制卡点 → 编码可空、建档可拖、派工可不选风场
  R3 无过程数据 → 事后补录（商务部 62 条日报平均滞后 16.7 天，52% 集中补交）
  R4 无统一口径 → 同一指标各算一套，会议用于对数
        ↓ 四类后果
  数据失真（账实 92%）｜协同靠会议｜成本年底才知道｜客户响应慢
```

| 编号 | 假设 | 验证指标 | 失败信号（触发调整） |

## 四、架构

### 4.1 进程与模块（沿用 C-02 + V3.3 增补）

```
protech-app（模块化单体，18 个 Maven 模块：module-sys/mdm/crm/contract/project/plm/process/scm/
  inventory/mes/aps/qms/eam/engineering/thd/cost/kb/bid/agent/integration）
protech-ai-gateway   唯一访问内网模型
protech-file-service OnlyOffice 回调 / PDF / 水印 / 照片
protech-job-worker   定时任务（提醒/升级/指标/对账/标讯调度/Agent 超时）
protech-bid-crawler  DMZ 标讯抓取器（可选，第 5 进程，同栈 Java 11 + SB 2.7.18）
```

**硬约束**：模块间只经 `api` 包接口或事件，禁跨模块 Mapper；单模块三层 controller→service→mapper。

### 4.2 部署与容量

| 项 | 值 |
|---|---|
| 在线/并发 | 200 / 100 QPS，余量 300 / 150（C-03） |
| 最小生产 | 8C32G + NAS，Docker Compose |
| 扩容触发 | 在线 >250 持续一周 或 CPU >70% → 无状态化双节点 |
| 环境 | dev（mock）/ test（脱敏）/ uat（抽样）/ prod（真实，主 Web 不出公网） |

### 4.3 DMZ 边界规则表（D-07，回应 F-01/F-30）

| 方向 | 主体 | 目的 | 端口/协议 | 鉴权 | 审计 |
|---|---|---|---|---|---|
| 入向 | 微信小程序 | `/api/mp/*`（登录/项目/文档/日志/照片/销项/整改） | 443/HTTPS，WAF 前置 | JWT + `X-Client: MP` + R17 数据范围强制 PROJECT | 全量 |
| 入向 | Agent 平台 | `/api/agent/v1/*` | 443/HTTPS，IP 白名单 | OAuth2 token + HMAC 签名 + 防重放 | `agt_call_log` |
| 出向 | bid-crawler | 白名单源站（Q-28 清单） | 443/HTTPS，仅 GET | crawler 专用证书 | 抓取日志 |
| 内部 | crawler → app | 拉取任务 + 回传结果 | mTLS | 证书 + 签名 | `int_sync_log` |
| 禁止 | 任意 | 主 Web 出公网、内网主动连 DMZ 管理端口、代理池绕过 | — | — | — |

> 若 Q-31 决策改为"仅内网"，需改 3 处：本表入向第 1 行、M10 小程序章、M19 入口限制；其余不变。

## 五、数据规范

### 5.1 通用字段与类型（全模块强制）

| 项 | 规定 |
|---|---|
| 主键 | `id BIGINT UNSIGNED AUTO_INCREMENT`；业务编码独立字段 |
| 软删除 | `deleted TINYINT DEFAULT 0`；审计日志/`bid_raw` 豁免（后者 90 天物理清理） |
| 审计 | `created_by/created_at/updated_by/updated_at`；`created_by VARCHAR(64)` |
| 金额 | `DECIMAL(18,2)` 元；禁 float/double；比例 `DECIMAL(6,4)`；数量 `DECIMAL(14,3)` |
| 时间 | `DATETIME`，`Asia/Shanghai`；不用 TIMESTAMP |
| 枚举 | `VARCHAR(24)` 存英文 code，字典表给中文 label |
| JSON | `JSON` 类型不建索引；需检索字段必须拆列 |
| 外键 | **禁止**（应用层保证，便于迁移） |
| 迁移 | Flyway 只增不改；索引命名 `idx_/uniq_{表}_{字段}` |

### 6.2 统一响应与错误码

```json
{ "code": 0, "message": "ok", "data": {}, "traceId": "a1b2" }
```

| HTTP | code | 含义 | 附加 |
|---|---|---|---|
| 200 | 0 | 成功 | — |
| 202 | 0 | **异步任务已接受**（仅任务创建类，F-19） | `data.task_id` |
| 400 | 1001 | 参数校验失败 | `data.errors[]` 字段级 |
| 401 | 2001 | 未登录/过期 | — |
| 403 | 2002/2003 | 无权限/范围外 | `data.missingPerm` |
| 404 | 3001 | 不存在 | — |
| 409 | 4001 | 并发冲突 | `data.currentVersion` |
| 422 | 5001 | 业务阻断 | `data.blockCode` + `suggestion` + `link` |
| 429 | 6001 | 限流 | `data.quota` |
| 500 | 9001 | 系统错误 | 仅 traceId |

**blockCode 命名空间（F-27）**：`BR-01…BR-09` 业务卡点｜`AGT-FORBIDDEN/AGT-QUOTA/AGT-EXPIRED` Agent 边界｜`BID-ROBOTS/BID-PARSE-FAIL` 标讯｜`SYS-*` 平台。

### 6.3 通用约定

| 项 | 规定 |
|---|---|
| 方法 | GET 查/POST 建与动作/PUT 全量/PATCH 局部/DELETE 仅停用语义 |
| 分页 | `pageNum`（1）`pageSize`（20，max 200）；返回 `total` |
| 幂等 | 写操作支持 `Idempotency-Key`；库存/导入/推送/Agent 任务必带 |
| 乐观锁 | 单据带 `version`，影响行数 0 → 409 |
| 超时 | 普通 10s；AI 30s（图像 20s）；文件转换 60s；导出异步 |
| 版本 | `/v1` 不兼容变更升 `/v2`，旧版保留 ≥6 个月 |
| 校验 | 见 V4-07 §4（10 类通用校验规则） |
