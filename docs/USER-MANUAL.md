# 第一章 系统概述

## 1.1 系统定位

Protech 是一套覆盖**订单全生命周期**的企业综合业务管理系统，从商机挖掘到售后闭环，贯通 18 个业务模块。

```
┌─────────────────────────────────────────────────────────────────┐
│                    订单全生命周期业务流                            │
│                                                                   │
│  招标情报 ──→ 商机 ──→ 报价 ──→ 合同 ──→ 项目立项                │
│                                   │                               │
│                                   ▼                               │
│              BOM 设计 ──→ 工艺路线 ──→ 采购 ──→ 生产制造          │
│                                            │                      │
│                                            ▼                      │
│              检验放行 ──→ 入库 ──→ 发货 ──→ 工程安装 ──→ 验收    │
│                                            │                      │
│                                            ▼                      │
│              成本归集 ──→ 九板看板 ──→ 售后服务                   │
└─────────────────────────────────────────────────────────────────┘
```

首次登录（或管理员重置密码后）→ 系统跳转独立改密页面（无侧栏/顶栏）：

| 要素 | 规则 |
|---|---|
| 原密码 | 必填 |
| 新密码 | ≥8 位，含字母 + 数字，实时强度提示 |
| 确认新密码 | 须与原密码一致 |
| 跳过/取消 | **无此选项**（必须修改后才能使用系统） |
| 失败 5 次 | 锁定 15 分钟 |

# 第三章 商务与合同管理（R04/R05）

## 3.1 商机管理

**路径**：② 合同与项目 → 商机管理

### 新建商机

1. 点击「商机登记」按钮
2. 填写：商机名称（必填）、客户主体（从下拉选择）、联系人、预计金额
3. 点击保存 → 系统自动生成编号 `OPP-{YYYYMM}-{4位}`

### 商机跟进

- 列表点击某行 → 右侧面板显示**跟进时间线**
- 点击「跟进」按钮 → 填写跟进类型 + 内容
- 丢单 → 填写丢单原因 → 状态变为 LOST
- 重激活 → LOST 状态可重新打开

### 销售漏斗

右侧面板实时显示：跟踪中数量/金额 → 已成交数量/金额 → 赢单率

## 3.2 报价单管理

**路径**：② 合同与项目 → 报价单台账

### 新建报价单

1. 点击「新建报价单」
2. 选择客户主体 + 填写产品线 + 交货条款 + 有效期
3. 添加明细行（物料/数量/单价/备注），系统自动计算 `行金额 = 数量 × 单价 × (1 + 税率)`
4. 提交 → 系统生成编号 `QT-{YYYYMM}-{4位}`

> ⚠ **金额一致性校验**：行合计（含税）必须 = 主表金额，不一致时拒绝保存

### 定标流程

```
提交评审 → [审批流] → 定标 WON → 自动生成合同草稿（FR-CRM-19）
         →           → 未中标 LOST → 必填原因（回流报价库）
```

## 3.3 合同管理

**路径**：② 合同与项目 → 合同台账

### 合同全生命周期（九节点）

```
DRAFT 编辑中 → REVIEWED 已评审 → SIGNED 已签署 → PERFORMING 履行中
     → ACCEPTED 已验收 → WARRANTY 质保期 → CLOSED 已关闭
                                                         ↓
                                                   CHANGED 已变更
```

### 合同评审（BR-01 卡点）

1. 编辑中的合同 → 点击「提交评审」
2. **BR-01 检查**：合同必须关联至少 1 个项目编码
   - 未关联 → 阻断条显示 `BR-01` + 「去建档 →」链接
   - 跳转建档后返回，已填内容**全部保留**
3. 已关联 → 进入审批流（两级：工程主管 → 总经理）
4. 全部通过 → 状态变为 REVIEWED

### 用印登记

REVIEWED 状态 → 点击「用印登记」→ 系统生成合同编号 `PRT-{YYYY}-{性质}-{业务}-{4位}` + 写入建档时限

### 26 要素建档备案（BR-02 卡点）

用印后 → 点击「建档备案」→ 进入 26 要素表单：

```
┌──────────────────────────────────────────────┐
│ PRT-2026-XS-NEW-0001  DT-BR02               │
│                                    ████████░ │ ← 完整度进度条
│                                    18/26 · 缺 8 │
├──────────────────────────────────────────────┤
│ ┌─ 基本要素 ──────────────────────────────┐ │
│ │ 合同名称 ✅  合同性质 ✅                 │ │
│ │ 甲方 ✅      乙方 ✅                     │ │
│ │ 金额 ✅      税率 ✅                     │ │
│ │ 付款条件 ✅  签订日 ✅                   │ │
│ │ 生效日 ✅    交货地址 ❌ ← 点击定位      │ │
│ │ 质保期 ❌    联系人 ❌                   │ │
│ └──────────────────────────────────────────┘ │
│                                              │
│ [提交备案]  ← ≥18/26 才可提交              │
└──────────────────────────────────────────────┘
```

> ⚠ **BR-02 冻结**：用印后第 4 个工作日未完成建档 → 开票冻结

### 开票与收款

- 建档完成后可申请开票
- BR-02 冻结时 → 整页阻断态（非 toast），三条出口：去补建档 / 查看冻结清单 / 申请解冻（R02）
- 收款确认由 R15 财务操作

## 3.4 招标情报

**路径**：② 合同与项目 → 招标情报

### 数据源管理

| 操作 | 说明 |
|---|---|
| 登记数据源 | 填写类别（A 业主/B 主机厂/C 公共平台/D 人工）+ 入口 URL |
| robots 审核启用 | robots 状态码 = 200 才可启用（合规） |
| 停用 | 随时可停用 |

### 标讯入库（四层去重）

```
入库请求
  │
  ▼
┌─ 层 1：URL 归一 ──────────────────┐
│  小写化 / 去 utm / 去尾斜杠      │ → 命中 → URL_DUPLICATE
└───────────────────────────────────┘
  │ 未命中
  ▼
┌─ 层 2：内容哈希 ──────────────────┐
│  SHA-256(url + content)          │ → 命中 → HASH_DUPLICATE
└───────────────────────────────────┘
  │ 未命中
  ▼
┌─ 层 3：跨源合并 ──────────────────┐
│  同业主 + 同项目 + 同标段        │ → 命中 → EXACT_MERGED
└───────────────────────────────────┘
  │ 未命中
  ▼
┌─ 层 4：变更关联 ──────────────────┐
│  补遗公告 → parent_id 关联       │ → 新公告 → NEW
└───────────────────────────────────┘
```

### 打分与转商机

- 入库成功后自动打分（100 分制：关键词 25 / 区域 25 / 金额 15 / 截止期 15 / 业主 10 / 机型 10）
- 级别：**≥70 HIGH**（高匹配）/ 50-69 MEDIUM / <50 ARCHIVED
- 点击「转商机」→ 一键生成商机（source_type=BID 自动写回）
- 反馈「有效/误判」→ is_correct 校准（模型迭代数据源）

# 第四章 供应链与库存管理（R09/R10/R11）

## 4.1 供应商五阶准入

**路径**：④ 供应链 → 供应商台账

```
第 1 阶 ──→ 第 2 阶 ──→ 第 3 阶 ──→ 第 4 阶 ──→ 第 5 阶
  注册       资质审核     样品送检     小批试用     合格供方
```

每点击「推进准入」进入下一阶段。第 5 阶完成后进入合格供方名录。

## 4.2 采购管理

### 采购需求（四来源）

安全库存触发 / MO 缺料 / 请购 / 手工——均通过「新建采购需求」录入。

### 采购订单（PO）

1. 新建 PO（项目 + 供应商 + 金额）
2. 下发订单（状态 → DISPATCHED）
3. 到货确认 → 生成入库事务

## 4.3 库存管理

### 库存事务（T+ 权威，幂等）

| 字段 | 必填 | 说明 |
|---|---|---|
| 事务类型 | ✅ | IN_PURCHASE / OUT_ISSUE / IN_RETURN / OUT_SALE |
| **幂等键** | ✅ | 来源单号+行号+动作；重复提交返回首次结果 |
| 法人 / 仓库 / 物料 | ✅ | — |
| 数量 | ✅ | 正数=入库，负数=出库 |
| 计量单位 | ✅ | E-20 受控 8 种 |
| 来源类型 | ✅ | PO / MO / MANUAL |

> **BR-INV-02**：出库时校验可用量，不足则拒绝（不允许负库存）

### 盘点全链路

```
新建盘点单(CT编号) → 开始盘点 → 录入实盘 → 复核
                                      │
                          ┌───────────┤
                          ▼           ▼
                     有差异行      无差异行
                          │           │
                    归因必填(E-37)   直接关闭
                          │
                    生成差异单(DF编号)
                          │
                    L1/L2/L3 审批
                          │
                       闭环完成
```

> ⚠ **E-37 无归因不调账**：差异行未填写六类归因之一（DOC_LAG/REPLENISH_UNBOOKED/MIX_ENTITY/PICK_ERROR/LOST/MEASURE）→ 复核被 422 拦截

### 呆滞处置

```
登记呆滞(CANDIDATE) → 确认(需E-38归因) → CONFIRMED → 发起处置(E-39方式) → DISPOSING → 审批 → DISPOSED
```

## 4.4 补货管理（BR-05）

- 补货申请必须**挂项目档案**（BR-03：无项目编码不得报销/发料）
- 安全项 24h 未回填 → 锁定（不可新建补货）

# 第五章 生产与排程管理（R12/R10）

## 5.1 生产订单

**路径**：⑤ 生产质量 → 生产订单

### 创建 MO

三种类型：STANDARD 标准 / BATCH 批量 / ENGINEERING 工程

创建后可生成工序路由（按步骤序列自动生成工序工单）。

### 工序报工

```
工序 PENDING → [开工] → STARTED → [报工] → FINISHED
                                             │
                                    needInspection=1
                                             │
                                    QC 检验放行 → 下一道工序
```

- 报工填合格量 + 不良量
- 有检验标记的工序 → QC 审核后才可继续

## 5.2 Andon 管理

拉响 Andon → 分级升级（工位→班长→主任）由 job 每 10 分钟扫描推进

## 5.3 APS 排产

### L1 粗排

选择多个生产订单 → 系统按优先级→订单→工序序顺排，自动选最小负载资源

**冲突检测**：
- CAPACITY_OVER：资源日产能超载
- MATERIAL_SHORT：齐套缺料

### L2 细排

- 拖拽甘特条形图 → 松手调 /adjust 端点（版本+1，状态→ADJUSTED）
- 已发布排产不可调整

### 发布

- 存在齐套缺料（qms_material_check.is_ready=0）→ 422 阻断
- 通过 → 状态 PUBLISHED

# 第十二章 常见问题

## Q1：为什么我看不到某些菜单？

菜单按权限码动态渲染。请联系管理员在「系统管理 → 角色权限」中为您的角色分配对应菜单权限。

## Q2：操作被"阻断"了怎么办？

系统用 422 + blockCode 标识业务卡点（非系统错误）。阻断条会显示：
- `blockCode` 徽标（如 BR-01）
- 一句话原因
- 「去处理 →」直达链接

按链接补齐前置条件后返回，已填内容**不会丢失**。

## Q3：为什么价格显示为 `***`？

`***` 表示**该字段受权限限制**（BR-06 价格脱敏）。说明文字只在列头出现一次。若需要查看价格，请联系管理员开通对应权限（如 `cost:view` 或 `scm:order:view_price`）。

## Q4：金额显示为 `—` 是什么意思？

`—` 表示**该字段没有值**（尚未发生/不适用），与 `***`（有值但无权限）不同。不要把 `—` 读成"金额为 0"。

## Q5：暗色主题下有些颜色不对怎么办？

系统 24 组主题已过对比度校验。如发现个别组件颜色异常，请截图反馈。已知约束：主按钮禁用 `opacity`、焦点环取中性色（非主色）。
